# Bots that manage themselves: what OpenClaw 2026.10.6 allows a plugin

Research behind `docs/design/main-bot-onboarding.md` (issue #292). It answers what a Clawtrate plugin can do on OpenClaw 2026.10.6: register tools, limit them per bot, reach the gateway's own methods and with whose authority, run a model with no tools, keep records, and serve external agents over MCP.

`<openclaw>/…` is a path in the OpenClaw 2026.10.6 package this repository pins for the development gateway: CI installs `openclaw@2026.10.6` from npm (`.github/workflows/ci.yml` line 61), registry integrity `sha512-jSpQPa2Jw5rG0J2GC07j9+qHtVYIuoHjgccU88JeS+p7188sBCnvIJeuaiNPHj1zsWkuHcBv443QiEUh7qrxwA==`. The repository itself pins only `@openclaw/gateway-client` and `@openclaw/gateway-protocol`. The development gateway used for the live checks was installed separately; its `dist/` and `docs/` were compared with that npm package file by file and are identical, so every line number here holds for the pinned package. Chunk names carry a build hash, so search by the `//#region` marker if a name changes. **Live** means it was confirmed on a named development gateway, which was reset afterwards. **Source** means it was read only.

## Method

- The live findings were confirmed on a named development gateway with a scripted model, through three paired devices of the check's own (read; read and write; read, write and admin), which were removed afterwards. The instance was then reset.
- Finding 6 is a privilege boundary. It is described here in words, with the pinned source lines.
- [`bot-self-management/fixture.mjs`](bot-self-management/fixture.mjs) is a stand-in for the contract the design draws from these findings. It records what a bot's tool would propose, checks that only an authenticated admin can apply it under the write's own precondition, and checks that Undo restores the journaled value only when nothing changed since. It talks to no gateway and makes no privileged call: `node docs/research/bot-self-management/fixture.mjs`.

## What this means for the plugin

- **A turn's scopes don't authorize a write.** They are the connection's authority (4), they come with routines (18), and with no operator they reach admin anyway (6). An admin's chat can also carry untrusted text. So the plugin's tools only read and propose, and every write happens in a plugin method called by a person with admin after a decision bound to the exact values (7), rechecked at the effect.
- **The plugin draws every boundary itself**: the bot from the context (1), which bots it may propose for (5), and each proposal's binding.
- **The plugin approval card isn't that binding** (20): it is resolved at `operator.approvals` and isn't tied to an admin principal and the values.
- **Proposals are durable plugin records** with an atomic claim (22). The preconditions the gateway checks inside a write (23, 27, 28) bind a file, a routine or the config's content, never the bot's incarnation, which lives outside the config (34); `agents.update` and `cron.remove` take none (24, 27). So on 2026.10.6 the plugin applies no stored request to an existing bot, and a person saves it in their own editor instead.
- **Describe is gated.** A completion with no tools exists (8, 25), but the plugin can't make it refuse a route other than the one shown (31).
- **A bot Clawtrate named starts as itself** (35-38): after `agents.create`, Clawtrate writes the name into `IDENTITY.md` with `agents.files.set` held to the template's hash (R23), and OpenClaw ends the first run before the bot's next turn. The picture stays in the config identity.
- **External agents**: the gateway's attach grant is loopback-only, bound to one task, and acts as the bot with no operator (10, 6); plugin HTTP routes can't carry admin (11).
