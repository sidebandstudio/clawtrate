# Bot voice: adding text to the bots' system prompts

Research for the voice plugin (`plugins/clawtrate-voice`, checklist row F-527). The bots on a gateway should talk to their person in a plain, friendly voice and never use an em dash, including bots that already exist. The questions are which mechanism OpenClaw 2026.10.6 gives a plugin to add the same text to the agents' system prompts, where that text does not reach, and what it costs in permissions.

`<openclaw>/…` is a path in the OpenClaw 2026.10.6 package (`OpenClaw 2026.10.6 (fe06181)`), the version `docs/decisions.md` pins. Chunk names carry a build hash, so search by the `//#region` marker if a name changes. **Live** means it was confirmed on a named development gateway (`pnpm dev-gateway start --instance voice --with-plugin clawtrate-voice`), which was reset afterwards. **Source** means it was read only.

## What follows

- The plugin registers `before_prompt_build` and returns `voice.md` as `appendSystemContext` while the setting is on. It reads nothing from the event, so the conversation grant gives it nothing it uses.
- The grant is the gateway owner's to give. Clawtrate never writes it, at install or later: it is an admin config write that lets a hook receive conversation data. Only the development gateway sets it, for its own instances. The plugin reports the hook's state from the config it was loaded with (finding 3), and Settings says what to set when the hook can't run.
- The setting is one row in the plugin's keyed store, one for the whole gateway, so bots made later are included. No row means on.
- A run gets the guide when its runner invokes the permitted prompt hook and sends the prompt that results, and no other way. Findings 9 and 10 are where it doesn't reach: a CLI backend that never sends a system prompt, a resumed CLI session that sends it only at its start, raw model runs, settled-tool finalization, side questions, control operations and sessions bound to an outside agent harness. Clawtrate says no more than that.
- Reading needs `operator.read`, and changing needs `operator.write`. That is the smallest scope that changes state. The change is between two fixed texts and can't add text of its own, and a writer can already tell any bot how to talk. A change also needs a person's own connection, as in `clawtrate-bots`, so a bot's turn can't switch it off (`docs/research/bot-self-management.md`, finding 6).
