# Bringing an existing OpenClaw in: what the gateway offers

Research behind `docs/design/bring-your-openclaw.md` (issue #487). It answers what OpenClaw lets a client do when a person arrives with a working gateway: read what one bot knows (its memory, the person's profile, its notes and skills) and write it into another bot, and move a scheduled job from one bot to another and back. Every finding holds on OpenClaw 2026.10.6 and 2026.11.10 unless it says otherwise.

`<openclaw>/…` is a path in the `openclaw@2026.10.6` npm package, registry integrity `sha512-jSpQPa2Jw5rG0J2GC07j9+qHtVYIuoHjgccU88JeS+p7188sBCnvIJeuaiNPHj1zsWkuHcBv443QiEUh7qrxwA==`, the same package CI installs. `<openclaw-11.10>/…` is a path in `openclaw@2026.11.10`, integrity `sha512-/FKDjxY1ZdUSXHx1a9b4EUpPRZywM3uv4181g22XImJfp/5+h+fFUZ7B7HthNrdYzq//05zH0Yf7mefzIlWFaQ==`, whose `dist` is minified, so it is cited by chunk and function name. Each was installed into a scratch folder and run under Node 24. Chunk names carry a build hash, so search by the `//#region` or `//!src` marker if a name changes.

**Live** means the probe [`bring-your-openclaw/bring-probe.ts`](bring-your-openclaw/bring-probe.ts) saw it on a named development instance with the scripted model, started with `--with-plugin clawtrate-memory` and `FS_SAFE_NATIVE_MODE=require`, through paired devices of its own at the read, write and admin tiers, which it removed afterwards. The instance was reset afterwards. **Live on both** means it was seen on an instance of each version. **Source** means it was read in the package only. On the development gateway the bot `otto` played the bot a person already has, and `main` played the Main Bot.

### The bot's own record of its memory files

| #   | What | Evidence | Kind |
| --- | ---- | -------- | ---- |
| B29 | **A bot keeps a record of its own last write to `MEMORY.md` and `USER.md`, and a file changed from outside drops out of its tasks after the bot's next write.** The record holds the file's hash and an origin class. A write through the bot's own file tools records `agent` only when there was no record, or the record was `agent` and its hash equals the file as it was before this write; otherwise `untrusted`, and an `untrusted` file stays so.
