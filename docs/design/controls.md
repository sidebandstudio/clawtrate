# Controls

What a person controls about each bot: what it may do with its tools, what it has been allowed, what it remembers, where it runs, and what it uses. This is the fourth part of the design, after `visual-language.md`, `conversation.md`, `bots.md` and `work-pane.md`, in the same language and with the same tokens. It is the part the reference product does not have: the teardown's "What users say is missing" (`docs/research/grok-bot-flows.md`, FC-01 to FC-15) says what people ask for, and the capability map (`docs/research/gateway-capabilities.md`) and the installed OpenClaw 2026.10.6 say what the gateway can do.

What must be true is in `docs/parity.md`: the tool-rule rows F-174 to F-180, F-222, F-328, F-330 to F-337, F-414 and F-416; the grant and audit rows F-166, F-167, F-178, F-324, F-326, F-327 and F-415; the default rows F-051, F-162, F-173, F-180, F-331, F-339, F-340 and F-365; the bot-to-bot rows F-130, F-309 to F-312 and F-436; the memory rows F-008, F-110, F-211 to F-216, F-375 to F-379, F-454 and F-455; the machine rows F-046, F-047, F-156, F-157 and F-272 to F-274; and the usage and budget rows F-131, F-232 to F-237, F-396 to F-398 and F-459. This document decides appearance, wording and input, and for every state it names the gateway fact the state rests on. Section 20 lists those facts with their sources, including what a probe plugin showed on a development gateway. Section 21 is the three plugins this needs, as requirement lists. Section 22 is the parity rows: each row's check, and the dependency cells that change. Section 23 is for builders.

One rule sits above the rest: **a screen states a guarantee only when something enforces it with nothing of Clawtrate's running.** That is the gateway's own code: its allow and deny lists, a bot's command policy, a bot's messaging list, a machine's approvals file. Anything a Clawtrate plugin adds holds only while that plugin runs, and the live probe in section 20 shows that when a plugin stops, the gateway runs the tool calls it would have asked about, with no card (row 33). So every line says which of the two holds it; a line that depends on a plugin says so on the line, and the page shows the plugin's state. Anything Clawtrate can only display or apply to its own sends says "Shown only". What is stored, what is loaded into a task, what is searchable, what is recorded and what is inferred are always told apart.

Model and effort per bot, the bot's account and its lock, and T3 Code are in `bots.md` sections 9 to 18 and are not redesigned here. Section 1 says where these pages sit beside them.

The prototype shows all of it: `prototype/controls.html` is the app with these screens added, and its address picks any state (section 23). The styles are in `prototype/css/controls.css` and the behaviour in `prototype/js/controls.js` (permissions, approvals, activity, messaging), `prototype/js/controls-memory.js` (memory) and `prototype/js/controls-usage.js` (usage, budgets, machines). `prototype/tools/checks/controls.mjs` checks them.

## 2. Shared rules

### What holds a rule

Every control on these pages is one of two kinds, and the design never mixes them on one line without saying so.

| Held by                      | What it covers                                                                                                                                                                                                                                                                                      | Holds when Clawtrate and its plugins are gone                                                                                      | How the gateway shows it                                                                                                                                           |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **The gateway**              | A bot's own deny list (`tools.deny`), the gateway's lists and tool profile for every bot, a bot's command policy (`tools.exec.mode`), a bot's outgoing messaging list (`tools.agentToAgent.send`), the gateway's pair setting, a machine's approvals file, a routine's grant, a machine's allowlist | Yes                                                                                                                                | A denied tool is removed from what the bot is offered; a command is refused or asked about by the gateway's own card; a send is refused with `status: "forbidden"` |
| **Clawtrate's rules plugin** | Asking before any tool other than commands, rules about what a tool acts on (a path, a command, a recipient, a server's tool), saved answers with a scope and a lifetime, "Ask when nothing else decides", the incoming messaging policy                                                            | **No.** With the plugin disabled, removed, failing to load or older than the rules need, the gateway runs those calls with no card | The plugin's card, or a refused call whose reason names the rule                                                                                                   |

The memory plugin and the budget plugin are the same kind: what they add holds only while they run (sections 12, 17).

**The plugin's state** is shown wherever a plugin rule is: at the top of a bot's permissions page, on every line that depends on it, and in Settings, Permissions. It comes from the plugin's own status method (section 21), never from the method list alone, because a method can be listed while its hook is not registered (section 20, row 34):

| State       | Established by                                                                                                                                | Shown                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Running     | `clawtrate-tool-rules.status` answers with a version the rules need or newer, its hook registered, and the time its hook last saw a tool call | "Clawtrate's rules plugin is running (version 1.2). It last checked a call at 5:46 PM." |
| Absent      | Its methods are not in `hello-ok.features.methods`                                                                                            | "Clawtrate's rules plugin isn't installed on this gateway."                             |
| Stopped     | Its methods are listed but `status` fails, or reports the hook not registered                                                                 | "Clawtrate's rules plugin isn't answering."                                             |
| Old         | `status` reports a version older than the rules need                                                                                          | "Clawtrate's rules plugin is version 0.9; Otto's rules need 1.0 or newer."              |
| Not checked | No answer yet in this session                                                                                                                 | "Checking Clawtrate's rules plugin…"                                                    |

**When rules need a plugin that is not running** (absent, stopped or old), the page does not pretend. It leads with a note on `--danger-soft`: "**Not being enforced right now.** 3 of Otto's rules need Clawtrate's rules plugin, which isn't answering. Until it runs, Otto can do these without asking:" then the affected actions by name ("Message other bots", "Change files under secrets/**", …), and one action, "Deny these until the plugin runs" (admin). That writes the affected tool groups to the bot's own deny list in one `config.patch`: a setting the gateway owns, which holds whatever happens to the plugin. While it is in place the lines read "Never", with "Until the rules plugin runs" under them and the gateway's mark, and when the plugin is Running again the note offers "Allow them again", which removes exactly those entries. A rule about what a tool acts on can only be held this way by denying the whole tool; the note says so ("To hold 'never under secrets/**', Clawtrate denies Change files entirely until the plugin runs.").

A bot can also be set to have Clawtrate do this by itself: "If the rules plugin stops, deny the tools its rules cover" (a switch on the permissions page, admin, on by default once a bot has a plugin rule). Clawtrate applies it whenever it is connected with admin and sees the plugin not running, and posts a grey line in the bot's open task, "Clawtrate denied Message other bots and Change files for Otto: the rules plugin isn't answering." The switch's line says what it is: "Clawtrate does this when it is open with admin access. The gateway doesn't do it by itself, so between the plugin stopping and Clawtrate noticing, these rules aren't enforced."

**What a plugin rule cannot cover**, said once on the permissions page under "For these rules to hold" (section 4), and never hidden:

- A bot that can manage the gateway or its plugins can change or remove the rules: its `gateway` and `plugins` tools must be Never.
- A bot that runs commands on the gateway's machine, as the gateway's user and outside a sandbox, can edit the gateway's settings and the plugin's store: Run commands must be Never there, or run on another machine or in a sandbox, for plugin rules to mean more than advice.
- A rule about a file tool is a rule about that tool, not about the file: commands and other tools can still reach the file where the bot may use them.

### Marks

Every rule, policy, saved approval, limit and budget carries one mark, in words with an icon, never in colour alone.

| Mark                                               | Icon                | Used for                                                                                                                        |
| -------------------------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| "The gateway enforces this"                        | shield              | A gateway-held control (table above). The only unqualified guarantee                                                            |
| "Only while Clawtrate's rules plugin runs"         | plug                | A rules-plugin control while the plugin is Running. The memory and budget plugins have the same mark with their names           |
| "Not enforced now: the rules plugin isn't running" | warning, `--danger` | A rules-plugin control while the plugin is absent, stopped or old                                                               |
| "Set on the gateway"                               | lock                | The gateway's settings for every bot, or a machine's approvals file: enforced by the gateway, shown, never changed by Clawtrate |
| "Shown only"                                       | eye                 | Something Clawtrate displays or applies to its own sends; nothing on the gateway holds it                                       |

The mark sits under a line's words in 12 px, `--text-faint` (the warning in `--danger`), with its icon; on a rule's page it is a fact row, "Held by", with the full sentence. A screen reader reads it as part of the line.

**Why Clawtrate does not change "Set on the gateway".** The gateway's settings for every bot and a machine's approvals file affect every bot and every person who uses the gateway. Clawtrate writes only a bot's own entries and its plugins' rules, and shows the gateway's with a padlock: "Set on the gateway. Clawtrate can't change it." (F-333)

### Four facts kept apart

Wherever a page shows a tool, a policy or a place, it keeps four facts apart and labels each, because they come from different records and can disagree (section 20, rows 1, 4 and 22):

| Fact                  | Means                                                                                                                                                 | From                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **Offered**           | The tool is in what the bot's latest task was offered                                                                                                 | `tools.effective {sessionKey}`, a cached listing, with its date        |
| **Default**           | A value for every bot that this bot inherits because it sets none                                                                                     | `config.get`, the gateway's settings for every bot                     |
| **Effective posture** | What the gateway will do for this bot's next call: the bot's own setting when it has one, else the default, then what a machine's approvals file adds | `config.get`, and the machine's file (admin) when it applies           |
| **Observed**          | Where a call actually ran, or what it actually did                                                                                                    | The call's own result in a task (`work-pane.md` §16), or the audit log |

"Narrow, never widen" is said only of the tool allow and deny lists, where the gateway's layering really works that way. A bot's own command policy replaces the default for that bot: it can be wider (section 20, row 4).

### Input

- A choice is one radio group with one tab stop; arrows move and choose; Home and End go to the ends. Choosing saves at once, except where section 5 asks first, and the save is announced only once the gateway's read-back agrees.
- A page's Back returns focus to the line that opened it. A save keeps focus on the control saved. A background read never moves focus.
- Fields that take a pattern or a number say what they accept before anything is typed, mark themselves invalid with the reason, keep focus, and save nothing until they are right.
- One polite live region announces: "Saved. Change files: asks first", "Couldn't save", "Revoked", "Removed", "Memory saved", "Deleted", "Budget saved", "Exported 7 files", and the access request's own phrases.

## 3. What a rule means

### The order, strongest first

The gateway decides; Clawtrate never works out a verdict of its own and never implies a check that did not happen. The first that applies decides, and a stronger one is never loosened by a weaker one.

| #   | What applies                                                                                                          | Held by                                                                                                                                                                                       | What the person sees                                                             |
| --- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 1   | The gateway's settings deny the tool for every bot: its deny list, its tool profile, its sandbox, its provider policy | The gateway: the tool is removed from what the bot is offered, and no later layer can grant it back                                                                                           | "Never", with the lock. Never a card                                             |
| 2   | A deny for this bot: a whole tool in its own deny list                                                                | The gateway                                                                                                                                                                                   | "Never". A call made anyway ends as a failed card that names the setting (below) |
| 2a  | A deny about what a tool acts on, for this bot or every bot                                                           | The rules plugin, while it runs                                                                                                                                                               | "Never" for those targets, with the plugin's mark                                |
| 3   | An ask for this bot or every bot                                                                                      | The rules plugin, while it runs; for commands also the bot's command policy, which the gateway holds                                                                                          | "Asks first". An ask outranks every allow below it                               |
| 4   | A saved answer to that same ask, in scope and not run out                                                             | The rules plugin, while it runs                                                                                                                                                               | Passes that ask only (section 6)                                                 |
| 5   | The automatic review, for commands only, when the bot's command policy is Review first (`auto`)                       | The gateway                                                                                                                                                                                   | The review's verdict: it runs, it asks, or it is refused                         |
| 6   | Nothing above                                                                                                         | Commands: the effective command policy. Other tools: they run, unless "Ask when nothing else decides" is on (the rules plugin); an allow rule passes a call past that switch and nothing else | Commands as their policy says. Other tools run, or ask                           |

- **For every bot and for one bot.** A deny or an ask applies wherever it is set; an allow for this bot never undoes an ask or a deny for every bot. (F-177, F-331)
- **Words are not permissions.** The gateway's command reviewer is given a bounded part of the task's earlier messages as evidence (section 20, row 39); that is input to its verdict and nothing more. Earlier words never pass a call by themselves and never override an ask or a deny. (F-180, F-339, F-340, F-414)
- **A saved answer that runs out or is revoked** leaves the order; the next call meets the order from the top. (F-326, F-327, F-415)

### Two layers for commands

A command passes two checks in turn: the rules plugin first, then the gateway's own command check (the bot's effective command policy, the machine's approvals file, its allowlist). Neither can wave the other through: a plugin allow never stops the gateway asking, and a command can meet two cards, each saying who asks.

### What "ask" shows, and to whom

**The card** is the approval card of `conversation.md` §12. For a plugin ask, its full request says "Asked by Clawtrate's rules plugin: Otto's rule 'Message other bots: ask first'." with "Edit rule". It offers only the decisions it can complete (section 6).

**Who sees it.** Shown live (section 20, row 30): the device whose message started the run receives the card and can answer it, and so does an admin connection; another device holding the approvals scope, and a read-only device, do not. A device that can send but not answer approvals cannot start a run whose plugin ask completes: the call is refused ("Plugin approval required (gateway unavailable)", row 32).

**How long it waits.** Shown live: the gateway sets the card's end to 10 minutes from when it is raised whatever the plugin asks for (row 31). The card's footer says "Waits 10 minutes; if no one answers, Otto doesn't do it." When it runs out the call is refused with "Approval timed out", and a late answer is refused with "approval already resolved".

**When nobody can be asked.** Shown live: in a routine's run the gateway raises no card and refuses the call at once, "Plugin approval unavailable: cron runs have no approval-capable initiating surface." (row 32). The routine's own summary may still claim the work was done. So in a routine an "Ask first" rule means refused, and the page that sets such a rule says so wherever the bot has routines: "Otto has 1 routine, Weekly cleanup. There, Ask first means refused: a routine's run has no one to ask, and the call is refused with no card. The routine's own summary may still say the work was done." A run started by another bot's message is not settled: once the recipient's card reached the admin connection, and on a repeat no card appeared within 40 seconds (row 32); the design treats it as possibly refused and the line's page says "When another bot's message starts Otto's run, Otto may not be able to ask; the call is then refused."

### A change while a card waits

Shown live (row 33): any configuration change saved while a plugin card waits (the bot's deny list, or the plugin turned off) ends the waiting call. The gateway still acknowledged the answer given afterwards, and the call then failed with "Plugin approval required (gateway unavailable)". A change to the plugin's own rules that is not a configuration change left the waiting call to its card, and Allow once ran it.

So:

- An answer and what then happened are two facts, shown apart (section 18).
- Saving a setting while a card waits warns first, in the save line: "Saved. Otto had a request waiting in 'Disk almost full on the media box'; changing settings ends a waiting request, so it will not run even if it is answered." with "Show the request".
- A change never stops a call already running.

### What a refused call looks like

A refused call never runs. In the transcript it is the action card's Not run outcome (`conversation.md` §7.3), shown as failed so it stays in view, and its opened view says what decided it, from what was reported at the time:

| Refused by                                                       | The card                               | "Decided by" line                                                                                                                                                                                                                           | What the gateway reported (Raw)                                                  |
| ---------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| The gateway's settings for every bot, or the bot's own deny list | "Blocked by policy", "Not run"         | Recorded: "Removed from Otto's tools by Otto's settings (read 5:41 PM)." when the deny list Clawtrate read before the call names it. Inferred otherwise: "Otto's settings deny this tool now; Clawtrate didn't read them before this call." | `Tool read not found`, with no details; the audit log keeps no record of it      |
| A rules-plugin deny                                              | "Blocked by policy", "Not run"         | "Clawtrate's rules plugin: Otto's rule 'never under secrets/**'." from the reason the plugin returned                                                                                                                                       | `details.status: "blocked"` and the plugin's reason                              |
| A person, on the card                                            | "Denied"                               | "You denied it at 5:43 PM."                                                                                                                                                                                                                 | `details.status: "error"`, "Denied by user. The tool call did not run." (row 31) |
| No answer in time                                                | "Expired"                              | "No one answered within 10 minutes."                                                                                                                                                                                                        | "Approval timed out"                                                             |
| Nobody could be asked                                            | "Not run"                              | "No one could be asked: a routine's run has no place to ask."                                                                                                                                                                               | The gateway's message as given                                                   |
| A change while it waited                                         | "Not run"                              | "The gateway's settings changed while it waited."                                                                                                                                                                                           | "Plugin approval required (gateway unavailable)"                                 |
| The bot's messaging list                                         | The Messaged card, "Blocked by policy" | "Otto may not message Pip: Otto's messaging settings. The gateway enforces this."                                                                                                                                                           | `status: "forbidden"` and the gateway's sentence naming the list                 |

The gateway answers "not found" both for a tool it removed and for a tool that never existed, so a not-found call is "Blocked by policy" only when a deny list Clawtrate read names that tool; otherwise it is the ordinary failed card with the gateway's message. (F-334, F-337)

## 4. What a bot may do

## 6. Asks, saved answers and rules: one contract

**Which asks can become a saved answer.** A person can turn an answer into a standing grant only where the rule allows it, and every card offers only what it can complete:

| Rule                                             | Who holds it     | On the card                                    | Can an answer be saved?                                                                                                 |
| ------------------------------------------------ | ---------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Ask, for a tool group or about what it acts on   | The rules plugin | Allow once, Always allow…, Deny                | Only when the rule says "Answers can be saved" (the default); a rule set to "Ask every time" offers Allow once and Deny |
| "Ask when nothing else decides"                  | The rules plugin | Allow once, Deny                               | No: it is a catch-all, and a saved answer would be a blanket allow                                                      |
| Messaging, "Ask me first" (outgoing or incoming) | The rules plugin | Allow once, Deny                               | No: each message is its own decision                                                                                    |
| Run commands, Ask or Review first                | The gateway      | The gateway's own card (`conversation.md` §12) | When the gateway offers it: an entry on the machine's allowlist, no expiry; a routine's request: a grant in whole days  |
| Any plugin ask in a routine                      | —                | No card: refused (section 3)                   | —                                                                                                                       |

**What a saved answer is bound to.** A Clawtrate grant records: the request it came from (its approval id); the bots it covers, Otto only or every bot; the ask rule it answers and that rule's version; what it acts on, the request's exact target (a path, a command, a recipient), which the form can widen only up to the rule's own pattern; and when it ends: one hour, one day or until revoked. It passes only that rule, at that version: when the rule is edited the grant stops applying and is shown as "Ended: its rule was edited". It never passes a deny or another rule's ask. (F-166, F-167)

**Who may save one.** For one bot: whoever answered the card, with the approvals scope; the plugin saves it only for the connection that answered that approval id. For every bot: admin only. Below admin the "Every bot" choice is shown disabled with "Saving for every bot needs admin access."

**What confirms it.** The gateway acknowledges an answer before the plugin has saved anything (its callback is not awaited, row 35), and an acknowledged Always allow ran the call once without saving anything (row 31). So the card says the grant is saved only when the plugin's list shows it: "Saved for Otto until 6:41 PM." Otherwise: "Saving it wasn't confirmed." with "Check again".

**One limit rule: refuse, and say so.** Nothing is ever removed by itself. Each scope (every bot, and each bot) holds at most 20 allow entries (allow rules and saved answers together), 20 ask rules and 50 Never rules, and a pattern is at most 1,000 characters (Clawtrate's choices). A save past a limit saves nothing and says why: "Otto has 20 allow rules, the most a scope can hold. Remove one to add another." (F-332) When the allow entries are full, the card says so before anyone answers, under its buttons: "Always allow will run this once and save nothing: Otto has 20 allow rules and saved answers, the most a scope can hold." with "Open the rules list". Choosing Always allow then runs the call once, as the answer allows, saves and removes nothing, and the resolved card repeats the limit with the same link; the next identical call asks again. (F-416)

**An expired card** offers no grant: nothing can complete one any more. It reads "Expired. Nothing ran." and, where the request offered a rule, "Make a rule…". That opens the rule form filled in from the request (the action, what it acted on, "Allow without asking"), needs the access a rule needs (admin; below admin the button is absent), saves only when the person chooses "Add rule", and never runs the expired call. (F-328)

**Rules about what a tool acts on**, on a line's page with the rules plugin running: one row per rule, Never first, then Ask first, then Allow, each with its version, when it was set and its last decided call. A rule for every bot is listed too, marked "A rule for every bot", edited in Settings, Permissions. "Add a rule" opens the form in place (F-174):

- "When Otto wants to:" the line's action;
- "acting on:" a pattern of the line's kind, its example as placeholder, and under it what it matches ("A path in Otto's workspace. * within a folder, ** across folders.", "A command. * matches the rest of a word or line.", "A bot's name.", "A tool of coder, or *");
- "It should:" Allow without asking, Ask first, Never; for Ask first, "Answers can be saved" or "Ask every time";
- "Note (optional)": the person's own words, shown beside the rule as "Note, not evaluated: …" and checked by nothing;
- "Add rule", disabled until the rule is complete, and "Cancel".

At the top of the form, one line says why a rule is built this way: "A rule is built from choices: nothing on the gateway can evaluate a sentence. Add a note in your own words if it helps."

A pattern matches the call's parameter as the tool receives it; the plugin matches nothing it cannot read as if it acted on everything (section 21). Without the plugin there are no such rules: "Rules about what it acts on need Clawtrate's rules plugin."

## 9. Activity

Activity lists the tool actions the gateway's audit log holds, newest first, and what caused each where a record says so (F-324).

**A row**: the time; the bot; the task; the action as the audit log names it (the tool, and the target only when the task's own transcript, readable by this connection, has it); a tag, **Allowed**, **Asked**, **Denied** or **Blocked**; and on the second line its cause, labelled:

- **Recorded**: a record shares this call's run and call identity: the rules plugin's decision ("Recorded: a saved approval, change files under notes/** (since revoked)"), the gateway's approval history ("Recorded: your answer, allow once"), or a review event.
- **Inferred**: Clawtrate saw the cause at the time and the records don't contradict it ("Inferred: Marlow's messaging list didn't name Pip when it was read at 5:30 PM").
- **Cause not recorded**: nothing joins. The row shows the tool and the time.

A cause names the rule version and grant it was recorded with, and stays readable after the rule is edited or the grant revoked ("rule version 2, edited since"). Nothing from a source this connection cannot read is shown: below the approvals scope an answer reads "Needs approvals access", with no command, approver or title.

**Filters**, in one band above the list that never covers it: a select for the bot, a select for the verdict (All, Allowed, Asked, Denied, Blocked), and a checkbox, "Only those allowed by a saved approval", which answers "what did this bot do that I allowed, and under which grant": each row then names its grant. On the phone the band takes as many lines as it needs, always above the list.

**Opened**, a row shows its facts (run, tool, the record's id, retained until) and "Show in chat" when the task's conversation holds that step.

**The foot**: "The gateway keeps 30 days of activity, up to 100,000 records, without arguments or results. A call to a tool the gateway removed leaves no record here." There is no Clear: the gateway has no method to clear its audit log, and Clawtrate keeps no history of its own here.

**States**: loading; couldn't load; empty; the gateway records none ("The gateway isn't recording activity: its audit log is switched off in its settings."); more than a page ("Show older"); a partial history ("Records before Oct 19 have expired.").

## 10. What a new bot starts with

`agents.create` takes only a name, a workspace, a model and a picture (row 36), so a new bot exists with the gateway's defaults for every bot until a second write gives it its own settings. Clawtrate makes that second write restrictive, and loosens in a third:

1. `agents.create`.
2. At once, one `config.patch`: Run commands Never, and the bot's deny list holding `gateway`, `plugins`, `automations`, `browser`, `message` and every tool server. Read back.
3. One `config.patch` to the defaults below, and the rules plugin's rules. Read back.

Clawtrate sends nothing to the bot and starts no task for it until step 2's read-back agrees. Between steps 1 and 2 the bot has the gateway's defaults; Settings, Permissions shows those defaults, and when they let a bot run commands without asking, New bot says before Create: "Until Clawtrate writes Viral's own settings, Viral has the gateway's defaults for every bot, which let a bot run commands without asking. Clawtrate writes them at once and starts nothing before."

| If            | The new bot's settings say                                                                                                                                                                               | Actions                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Step 2 failed | On `--danger-soft`: "Viral's restrictive settings weren't written. It has the gateway's defaults for every bot, which let it run commands without asking. Clawtrate won't send to Viral until they are." | "Write them again", "Delete Viral…" |
| Step 3 failed | On `--warn-soft`: "Viral is set restrictively: it can't run commands or manage anything. Clawtrate couldn't write the defaults below."                                                                   | "Write them again"                  |

The defaults:

| Setting                                       | New bot's value                                               | Held by                                                                                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Run commands                                  | Review first while the rules plugin runs; Ask when it doesn't | The gateway                                                                                                                                                             |
| Change the gateway's settings                 | Never                                                         | The gateway                                                                                                                                                             |
| T3 Code                                       | Off (`bots.md` §17)                                           | The gateway                                                                                                                                                             |
| Ask before running the gateway's command line | Ask every time, for commands that run `openclaw` (F-051)      | The rules plugin, while it runs; without it, Run commands is Ask, so the gateway's command policy asks for every command not on the machine's allowlist, these included |
| Everything else                               | The gateway's settings for every bot                          | The gateway                                                                                                                                                             |

No tool a bot is given creates a bot: `agents.create` is an admin method, not a tool, and the `gateway` and `plugins` tools read and change the gateway and its plugins (row 37). A bot creates another only through a command that runs the gateway's command-line tool, and by default such a command asks first. What holds that ask is said exactly: where the bot's commands are set to Ask, the gateway's command policy; where they are Review first, Clawtrate's rules plugin's ask, only while it runs. When the plugin stops, the bot's permissions page lists that ask under "Not being enforced right now" and offers to deny Run commands until it runs (section 2). A pattern on a command's text is advice against a bot that wants round it; Never is the guarantee. The list is in Settings, Permissions, editable (admin), kept as this person's preference with the gateway.

## 16. Usage and context

Usage is the gateway's own numbers with their source and age, every time a figure appears. A figure the gateway does not report reads "Unavailable"; a total that misses some runs says "Partial"; a figure still being counted says so. An account is named only when the gateway ties the figure to that account.

**A bot's Usage page**, top to bottom:

1. **The budget**, first, when there is one: its meter, its period, its mark, and its state (section 17). Without one, "Set a budget".
2. **Period**: Today, This week, 30 days. A week starts Monday 00:00 in this person's time zone. The budget and the figures below use the same records and the same period, so the week's total and the budget's count are the same number.
3. **Tokens**: Input, Output, Cache read, Cache write, Total, each in full; "From the gateway's usage records for Otto, as of 5:41 PM."
4. **Cost**: "About $3.29", and under it "The gateway's estimate from its configured prices, in US dollars, as of 5:41 PM.". "Partial: 2 runs have no price configured." when some are missing. A balance a provider reports is shown as that provider's own figure with its time. Clawtrate never computes a cost.
5. **By source** (F-131, F-237): "Your messages", "Routines" (runs whose task is a routine's), "Messages from other bots" (runs a send's result names), "Not attributed". A recipient task's whole total is never charged to one message.
6. **By task**, and **Context** for the open task ("41,200 of 128,000 tokens"; "What fills it isn't reported: the gateway counts input, output and cache, not history, memory or tools apart." F-233).

**Settings, Usage**: provider limits as the gateway reports them, each with its time ("OpenAI · Weekly · 62% used · resets Nov 20 · as of 5:40 PM"; "No limits reported" for one that reports none) (F-235); usage by bot, and by source; budgets.

**Near a provider's limit** (F-236): at 90 percent of a reported window (Clawtrate's choice), or when a run waits on a rate limit, a note above the composer of each bot whose account is that provider's: "OpenAI reports 92% of a weekly limit used, as of 5:40 PM. It doesn't say which of your OpenAI accounts." At the limit: "OpenAI reports a weekly limit reached, as of 5:40 PM. Runs that use it wait or fail until it resets, Nov 20." It is closed with its button until the figure changes.

## 17. Budgets

A budget is a number of tokens a bot or a routine may use in a day or a week (F-234). **By default a budget is a warning, and says so.** Stopping a bot at its limit is offered only where it can be shown to hold.

**Setting one**, on the bot's Usage page: Daily or Weekly, a number ("Tokens", whole, 1,000 or more), counting the total the gateway reports for the bot (or the routine). "Save budget".

**A warning budget** ("Shown only"), the default, kept as this person's preference:

- At 80 percent (F-396): a grey line in the bot's open task, "Otto has used 82% of its weekly budget: 1.64M of 2M tokens.", and a system notification on the desktop.
- At 100 percent (F-397): Clawtrate stops sending new messages to Otto from this device, and the composer says so: "Otto's weekly budget is used up, so Clawtrate won't send from here. This is shown only: other apps, channels and Otto's routines aren't stopped." with "Raise budget". With admin, "Pause Weekly cleanup".
- Resets daily at 00:00, weekly at 00:00 on Monday, in this person's time zone; refused sends are not replayed; raising it lets the next message go at once (F-398, F-459).

**A budget the budget plugin holds** is a choice a person makes knowingly ("Stop Otto at the limit"), offered only when the plugin is installed, running and permitted to read conversations, which its setup asks the gateway's owner for. Even then it holds only on the routes the plugin has proven on this gateway, and the budget says which, from the plugin's own coverage report (section 21):

"Stops Otto at the limit for runs from apps and channels (the gateway's own runner) and from the command line. Not for runs on the Codex harness: those are warned only."

| State of the plugin                            | The budget says                                                                                                                                     |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Running, permitted, its counter current        | The coverage sentence above, and the meter                                                                                                          |
| Installed, not permitted to read conversations | "The budget plugin can't stop Otto: the gateway's owner hasn't let it read conversations. This budget is a warning until they do."                  |
| Stopped or old                                 | "The budget plugin isn't running (or is older than this budget needs), so nothing stops Otto at the limit. This budget is a warning until it runs." |
| Counter behind                                 | "The plugin's count is from 5:12 PM; runs since then may not be counted, so Otto can pass the limit."                                               |
| A route not covered                            | Named in "Not for: …"                                                                                                                               |

At the limit, on a covered route, the gateway refuses a new run before the model is asked, and the task shows "Otto didn't start: its weekly budget is used up. It resets Monday at 00:00." A run already going is not stopped, and one run can pass the limit, because a run's usage is known only after it. When a person chose "Stop Otto at the limit" and the plugin stops holding it, the budget does not quietly become a warning: the bot's Usage row and page lead with "Otto's budget isn't being enforced now", in `--danger`.

**States**: under; warned; reached (warning); reached (enforced); each plugin state above; counted to an earlier time; an invalid number ("Enter a whole number of 1,000 or more.").

## 18. In the conversation

- **A refused call**: the action card's Not run outcome with section 3's "Decided by" line, recorded or inferred, and "Edit rule" (admin to change).
- **An ask**: the approval card with who asks ("Asked by Clawtrate's rules plugin: …"), its 10-minute footer, and only the decisions it can complete (section 6).
- **"Always allow…"** for a plugin ask that admits saving: a form under the summary with **For** ("Otto only", "Every bot", the latter for admin only) and **Lasts** ("1 hour", "1 day", "Until revoked"), the target it will cover ("Covers: changing notes/disk-2026-11-16.md. It answers this rule only, at this version, and stops applying if the rule is edited."), and "Allow and save", Back, Deny.
- **An answered card** has two lines, never one: "Your answer: Allowed once, 5:44 PM." and "Then: Ran" / "Then: Didn't run: the gateway's settings changed while it waited." / "Then: not reported yet". For Always allow, a third: "Saved for Otto until 6:41 PM." or "Saving it wasn't confirmed."
- **An expired card**: "Expired. Nothing ran." and, for admin where the request offered a rule, "Make a rule…", which opens the rule form filled in from the request and saves only when the person saves it. No grant is offered (section 6).
- **At the allow limit**: the card says before anyone answers that Always allow will run the call once and save nothing, names the limit, and links to the rules list (section 6).
- **Saved to memory** (F-110): a grey line where a file tool wrote `MEMORY.md`, `USER.md` or a note with a successful result, or where the memory plugin reports a write: "Saved to memory: memory/2026-11-17.md". It opens that item at that revision. A failed write gives no line; a write by a command gives none, because nothing reports it.
- **Budget lines and the provider note**: sections 16 and 17.
- **The Messaged card's policy states**: section 11.

## 21. The plugins

Each plugin is written from its list, each item checked by a test or a review, and each gets its own security review before it is installed on any gateway that is not a development gateway. Every one of them fails open when it is gone (row 33), so none of them is presented as a guarantee (section 2).

### Clawtrate's rules plugin (`clawtrate-tool-rules`, P5)

**What it must do.**

- [ ] One `before_tool_call` hook for every tool; no conversation access.
- [ ] Decide in this order: a matching deny (block, with the rule named); a matching ask, unless a grant made for that ask rule at its current version covers the call (`requireApproval`); "Ask when nothing else decides", unless an allow rule matches (`requireApproval`); otherwise no decision.
- [ ] Match on the canonical tool name and one parameter per kind (a file tool's `path` and the host's `derivedPaths`; `exec`'s `command`; `sessions_send`'s recipient resolved through the gateway's own label and alias resolution, refusing when it can't resolve; a server tool's name). A call whose parameter can't be read is treated as acting on everything.
- [ ] Incoming messaging: on the sender's `sessions_send`, apply the resolved recipient's incoming rules before the message leaves.
- [ ] Ask with a title of at most 80 characters, a description of at most 512 naming the rule and the target, `timeoutMs: 600000`, and `allowedDecisions` that include `allow-always` only when the rule admits saving and the scope has room.
- [ ] Save a grant only from `onResolution` receiving `allow-always` for its own request, bound as section 6 says, for the connection that answered that approval id; a grant for every bot only when that connection has admin. Report the grant in `grants.list` only once it is written.
- [ ] Refuse at every limit (section 6); never evict.
- [ ] Keep a metadata-only decision record for 30 days: time, bot, task, run, call id hashed as the audit log hashes it, tool, decision, and its source (a rule id and version, a grant id, the fallback, or none), so a cause can be joined to an audit record by run and call identity.
- [ ] `clawtrate-tool-rules.status` (read): version, rules schema version, whether its hook is registered, the time its hook last saw a call, and which tools it matches.
- [ ] Methods `get`, `decisions.list` (read); `set {scope, rules, expectedVersion}` (admin); `grants.list`, `grants.revoke` (approvals; admin for every-bot grants). An invalidation event at read scope that carries only `{scope, version}`; readers re-fetch.
- [ ] When its rules can't be read, block every call it would have decided.

**What it must never do.** Rewrite a call's parameters; get ahead of the gateway's own policy; ask or block for `ask_user`; let a grant or an allow outrank a deny or another rule's ask; mint a grant from anything but its own request's `allow-always`; store or log arguments or results; carry paths, commands or bot ids in an event a broader audience can read.

### Clawtrate's memory plugin (`clawtrate-memory`, P2)

**What it must do.**

- [ ] `list`, `read` (read, only within what that connection may read); `write {path, content, expectedHash}`, `delete {path, expectedHash}` (admin) for notes and shared folders.
- [ ] `move {item, from: {path, expectedHash}, to: {path, expectedHash}}` (admin): the one operation that writes `MEMORY.md` besides the gateway's own writer. Under one lock for the workspace: check both hashes; write the target with the item added, by a write to a temporary file and a rename; check the source's hash again and write it without the item; if the second write fails, restore the target from the copy it kept; report `{done}`, `{undone}` or `{both, target, source}` with the new hashes. The race with a write made outside the lock between the last check and the rename is stated, not hidden.
- [ ] `copyToRoots {item, agents[], expectedHashes}` (admin) for shared items: all or nothing; each copy marked with its source and an id so it can be removed exactly.
- [ ] Resolve a bot's workspace with `resolveAgentWorkspaceDir` and refuse a workspace the gateway reaches through a device bridge. Open with no-follow, refuse hard links, check after opening that the file is inside the root by its identity, and refuse a configured shared root that is a link or outside the gateway's state.
- [ ] Record a saver only for a successful write of that revision: its own writes, and an `after_tool_call` observation of a file tool whose result succeeded and whose file then has the recorded hash. The observation sees arguments and results; it keeps only the bot, task, time, path and hash.
- [ ] Report searchability only from a search or get that returned that revision.

**What it must never do.** Write outside notes, shared folders and `move`/`copyToRoots`; delete a folder; keep memory text anywhere but the files themselves; emit paths or text in a broad event; call a reindex the gateway's owner hasn't supported.

### Clawtrate's budget plugin (`clawtrate-budgets`, new)

**What it must do.**

- [ ] Count each model attempt's usage from `llm_output` by bot and routine, once per attempt (keyed by run and attempt), and mark a run whose usage never arrived as uncounted.
- [ ] Gate a new run with `before_agent_run` when the period's count reaches the budget; never stop a run already going.
- [ ] Prove, on its own gateway at start, which routes call its gate and its counter, and report that coverage in `status`: the routes covered, the time its counter last counted, whether it is permitted (conversation access granted), and its version.
- [ ] Methods `get`, `status` (read); `set` (admin). An invalidation event carrying only the target and version.
- [ ] Ask the gateway's owner, in its setup, for `allowConversationAccess`; without it, register no gate and report not permitted.

**What it must never do.** Keep, log or send any prompt, reply, argument or result; refuse anything but the start of a run; replay a refused run; count an estimated cost as tokens; report a route as covered that it has not seen call its gate.
