# Controls

What a person controls about each bot: what it may do with its tools, what it has been allowed, what it remembers, where it runs, and what it uses. This is the fourth part of the design, after `visual-language.md`, `conversation.md`, `bots.md` and `work-pane.md`, in the same language and with the same tokens. It is the part the reference product does not have: the teardown's "What users say is missing" (`docs/research/grok-bot-flows.md`, FC-01 to FC-15) says what people ask for, and the capability map (`docs/research/gateway-capabilities.md`) and the installed OpenClaw 2026.10.6 say what the gateway can do.

What must be true is in `docs/parity.md`: the tool-rule rows F-174 to F-180, F-222, F-328, F-330 to F-337, F-414 and F-416; the grant and audit rows F-166, F-167, F-178, F-324, F-326, F-327 and F-415; the default rows F-051, F-162, F-173, F-180, F-331, F-339, F-340 and F-365; the bot-to-bot rows F-130, F-309 to F-312 and F-436; the memory rows F-008, F-110, F-211 to F-216, F-375 to F-379, F-454 and F-455; the machine rows F-046, F-047, F-156, F-157 and F-272 to F-274; and the usage and budget rows F-131, F-232 to F-237, F-396 to F-398 and F-459. This document decides appearance, wording and input, and for every state it names the gateway fact the state rests on. Section 20 lists those facts with their sources. Section 21 is the three plugins this needs, as requirement lists. Section 22 lists the parity rows whose wording has to change. Section 23 is for builders.

One rule sits above the rest: **nothing is called enforced unless the gateway enforces it.** A rule the gateway applies says so; a rule a Clawtrate plugin applies on the gateway names the plugin; a limit Clawtrate can only display or apply to its own sends says "Shown only" and names what it does not stop. A control the gateway cannot honour is not drawn as if it worked.

Model and effort per bot, the bot's account and its lock, and T3 Code are in `bots.md` sections 9 to 18 and are not redesigned here. Section 1 says where these pages sit beside them.

The prototype shows all of it: `prototype/controls.html` is the app with these screens added, and its address picks any state (section 23). The styles are in `prototype/css/controls.css` and the behaviour in `prototype/js/controls.js` (permissions, approvals, activity, messaging), `prototype/js/controls-memory.js` (memory) and `prototype/js/controls-usage.js` (usage, budgets, machines). `prototype/tools/checks/controls.mjs` checks them.

## 2. Shared rules

### The enforcement mark

Every rule, policy, saved approval, limit and budget carries one mark, in words with an icon, never in colour alone. It says who holds the line, not who drew it.

| Mark                                     | Icon   | Means                                                                                                                                                                                       | Used for                                                                                                           |
| ---------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| "The gateway enforces this"              | shield | The gateway's own code refuses, removes or asks, for every app, channel and routine, whether Clawtrate is running or not                                                                    | A bot's tool deny, its command policy, its messaging list, a machine's allowlist, a routine's grant, where it runs |
| "Clawtrate's rules plugin enforces this" | plug   | A Clawtrate plugin on the gateway refuses or asks, for every app, channel and routine, while it is installed and enabled. The memory and budget plugins have the same mark with their names | Ask rules, rules about what a tool acts on, grants with a scope and a lifetime, budgets that refuse a run          |
| "Set on the gateway"                     | lock   | Part of the gateway's configuration for every bot, or of a machine's own approvals. The gateway enforces it, and Clawtrate shows it and never changes it                                    | The gateway's own deny lists, tool profile, sandbox, a machine that always asks                                    |
| "Shown only"                             | eye    | Clawtrate displays or warns, or holds back its own sends. Nothing on the gateway holds it, so other apps, channels and routines are not stopped                                             | A budget without its plugin, a usage warning                                                                       |

The mark sits under a line's words in 12 px, `--text-faint`, with its icon; on a rule's page it is a fact row, "Enforced by", with the full sentence. A screen reader reads it as part of the line: "Change files, allowed, the gateway enforces this."

**Why Clawtrate does not change "Set on the gateway".** The gateway's settings for every bot (`tools.deny`, `tools.profile`, `tools.exec`, a machine's approvals file) affect every bot and every person who uses the gateway, and the gateway makes them a ceiling that no later layer can grant back (section 20, row 1). Clawtrate writes only a bot's own entries and its plugins' rules, and shows the gateway's with a padlock: "Set on the gateway. Clawtrate can't change it." (F-333)

### Input

- A choice is one radio group with one tab stop; arrows move and choose; Home and End go to the ends. Choosing saves at once, except where section 5 asks first, and the save is announced.
- A page's Back returns focus to the line that opened it. A save keeps focus on the control saved. A background read never moves focus.
- Fields that take a pattern or a number say what they accept under them before anything is typed, mark themselves invalid with the reason when they are wrong, keep focus, and save nothing until they are right.
- One polite live region (the one `bots.md` §2 uses) announces: "Saved. Change files: asks first", "Couldn't save", "Revoked", "Removed", "Memory saved", "Deleted", "Pinned", "Copied", "Budget saved", "Exported 6 files", and the access request's own phrases.

## 3. What a rule means

### The order, strongest first

The gateway decides; Clawtrate never works out a verdict of its own and never implies a check that did not happen. The order below is the teardown's (section 8.8), mapped onto what the gateway and Clawtrate's rules plugin can each do. The first that applies decides, and a stronger one is never loosened by a weaker one.

| #   | What applies                                                                                                                 | Who enforces it                                                                                                                               | What the person sees                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1   | The gateway's configuration denies the tool for every bot: its deny list, its tool profile, its sandbox, its provider policy | The gateway: a denied tool is removed from what the bot is offered, and no later layer can grant it back                                      | "Never", with the lock: "Set on the gateway". Nothing in Clawtrate loosens it, and it never becomes a card |
| 2   | A deny for this bot or for every bot                                                                                         | A whole tool: the gateway, from the bot's own deny list. What a tool acts on: the rules plugin, which refuses the call before it runs         | "Never". A call made anyway ends as a failed card, "Blocked by policy", that names the rule (section 18)   |
| 3   | An ask for this bot or for every bot                                                                                         | The rules plugin; for commands also the bot's own command policy, which the gateway enforces                                                  | "Asks first". An ask outranks every allow below it, however specific                                       |
| 4   | A saved approval that is in scope and has not run out                                                                        | The rules plugin's grants; a machine's allowlist and a routine's grant, which the gateway enforces                                            | "Allowed by a saved approval", in the line's page and in Activity                                          |
| 5   | The automatic review, for commands only                                                                                      | The gateway, when the bot's command policy is "Review first"                                                                                  | The review's verdict: it runs, it asks, or it is refused (`conversation.md` §12)                           |
| 6   | Nothing above                                                                                                                | Commands: the gateway's command policy. Every other tool: it runs, unless "Ask when nothing else decides" is on, which needs the rules plugin | Commands as their policy says. Other tools run, or ask                                                     |

- **For every bot and for one bot.** A deny or an ask applies wherever it is set: a rule for every bot and a rule for this bot are the same level, and the stricter wins. An allow for this bot never undoes an ask or a deny for every bot. (F-177, F-331)
- **Words are not permissions.** Something the person said earlier in the conversation is input to the gateway's automatic review and nothing more. It never passes a call by itself and never overrides an ask or a deny. (F-180, F-339, F-340, F-414)
- **A saved approval that runs out or is revoked** leaves the order; the order is applied again from the top for the next call. That does not by itself mean a card: another saved approval in scope, or the review, may still decide. (F-326, F-327, F-415)

### Two layers for commands

A command passes two checks in turn: the rules plugin first (its asks and its rules about what a command matches), then the gateway's own command check (the bot's command policy, the machine's approvals, its allowlist). Each can refuse or ask; neither can wave the other through.

- A rules-plugin allow never stops the gateway asking. When the bot's command policy is Ask, the line's page says: "Otto's command policy asks for commands it hasn't allowed before. A saved approval here doesn't stop that."
- A command can meet two cards, one after the other. Each says who asks: the plugin's card "Asked because of Otto's rule 'ask before rm'", the gateway's card its own reason (`conversation.md` §12). The design never merges them.
- A machine whose own approvals always ask keeps asking whatever is saved; the line says so: "media-box always asks for commands. Saved approvals don't stop it." (Set on the gateway.)

### What "ask" shows, and to whom

**The card** is the approval card of `conversation.md` section 12, unchanged in form. Its title names the bot and the action ("Otto wants to message Pip"); its full request adds the line "Asked because of Otto's rule 'Message other bots: ask first'." with "Edit rule", which opens the rule (section 5), and when the rule is one for every bot, "Asked because of a rule for every bot". Its decisions are those the plugin offers: Allow once, Always allow…, and Deny, always. Always allow opens the form of section 18.

**Who sees it.** The gateway delivers an approval to admin connections, and otherwise only to connections with the approvals scope that are the device that started the run, or a device named as its reviewer (section 20, row 6). So the card appears for the person whose message started the run, on the device they sent it from, and on admin connections. Another person's device does not see it, and a read-only connection never does.

**How long it waits.** The plugin sets the wait and the gateway caps it at 10 minutes; Clawtrate's plugin asks for the whole 10 minutes. The card's footer says so: "Waits 10 minutes; if no one answers, Otto doesn't do it." When it runs out, the call is not run and the card reads Expired. This is shorter than an approval the gateway raises for its own command check, which can wait longer; the card states its own wait.

**When nobody can be asked.** A run that no person started from a device (a routine, a heartbeat) has no one to ask, and the gateway refuses the ask: the call is blocked and its result says why, in the gateway's words ("Plugin approval unavailable: cron runs have no approval-capable initiating surface."). The same happens when no connection that can answer approvals is open. So in a routine an ask rule works as Never. The line's page says this under the choice: "In routines, Ask works as Never: a routine's run has no one to ask." And the card in the routine's transcript reads Not run, "No one could be asked", with the gateway's sentence in its Raw. (Section 20, row 7.)

### A rule changed while a call waits

- A change applies to calls made after it is saved. A call already waiting on a card keeps its card, and the answer decides that one call. A change never cancels a card or stops a run already going (section 20, row 10).
- When the bot has a card waiting, the save line says so and leads to it: "Saved. Otto still has a request waiting in 'Disk almost full on the media box'; your answer there decides it." with "Show the request". Saving Never does not deny the waiting call; the person does, on the card.
- A rule saved while a call is running does not touch that call; its result comes as usual.

### What a refused call looks like

A refused call never runs. In the transcript it is the action card's Not run outcome (`conversation.md` §7.3), shown as failed so it stays in view, and its opened view says what decided it, in one line, "Decided by:", from what the gateway and the plugin report:

| Refused by                           | The card                               | "Decided by" line                                                                     | What the gateway reported (Raw)                                                                              |
| ------------------------------------ | -------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| The gateway's settings for every bot | "Blocked by policy", "Not run"         | "The gateway's settings deny read for every bot. Set on the gateway."                 | `Tool read not found`, with no details: the gateway removed the tool, so the call found nothing              |
| The bot's own deny                   | "Blocked by policy", "Not run"         | "Otto's settings: Never read files. The gateway removed the tool from Otto's tools."  | The same                                                                                                     |
| A rules-plugin deny                  | "Blocked by policy", "Not run"         | "Otto's rule: Never change files under secrets/." from the reason the plugin returned | `details.status: "blocked"`, `deniedReason: "plugin-before-tool-call"`, and the plugin's reason              |
| A person, on the card                | "Denied"                               | "You denied it at 5:43 PM." (or "Denied on another device at 5:43 PM.")               | `details.status: "blocked"`, `deniedReason: "plugin-approval"`, "Denied by user. The tool call did not run." |
| No answer in time                    | "Expired"                              | "No one answered within 10 minutes."                                                  | "Approval timed out"                                                                                         |
| Nobody could be asked                | "Not run"                              | "No one could be asked: a routine's run has no place to ask."                         | The gateway's message as given                                                                               |
| The bot's messaging list             | The Messaged card, "Blocked by policy" | "Otto may not message Pip: Otto's messaging settings. The gateway enforces this."     | `status: "forbidden"` and the gateway's sentence naming the allowlist (section 11)                           |

The first two rows rest on a reading the design states plainly: the gateway answers "not found" for a tool it removed, and Clawtrate says "Blocked by policy" only when the tool's name is on a deny list it has read (the bot's, or the gateway's for every bot). A "not found" for a tool on no deny list is the ordinary failed card with the gateway's message. (F-334, F-337)

## 4. What a bot may do

The Tools group of a bot's settings opens with one row, **What Otto may do**, whose value is the count strip in short ("6 without asking, 3 ask first, 3 never"). It opens the bot's permissions page. (F-176)

**The page.** Back, the title "What Otto may do", and under it the count strip and one line (13, faint): "From Otto's settings and the gateway's, read at 5:41 PM. Open a line for its exact rule." Then the lines, in four groups, each a group word and a fact block of rule lines:

| Group               | What is in it                                                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Without asking      | Tools Otto is offered and may use with no card: nothing denies them and nothing asks                                                                             |
| Asks first          | Tools whose use waits for a person: an ask rule, or for commands an Ask or Review first policy                                                                   |
| Never               | Tools denied to Otto: by its own settings, by a rule, or by the gateway for every bot                                                                            |
| Not offered to Otto | Tools the gateway does not give Otto at all (its tool profile, a plugin not loaded, a provider's tools for another provider), with why; shown folded, as a count |

So one screen answers three questions at a glance: what Otto does without asking, what it must ask for, and what it may never do.

**The lines** are tool groups in plain words, never the gateway's names, which are on each line's page. The groups come from the gateway's tool inventory for the bot (section 20, row 3), named by Clawtrate:

| Search the web                | `web_search`, `web_fetch`           |                                                                                                                                        |

| Look at its tasks             | `sessions_list`, `sessions_history` |                                                                                                                                        |

| Manage routines               | `automations`, `cron`               |                                                                                                                                        |

| Send messages on channels     | `message`                           |                                                                                                                                        |
| A tool server, by its name    | `<server>__*`                       | One line per server the gateway lists for Otto ("Coding agent coder"); T3 Code's is `bots.md` §17's switch and shows here as its value |

**A line's value.** "Allowed", "Asks first" or "Never", at the right. ## 6. Rules about what a tool acts on, and their limits

With the rules plugin, a line can carry rules about what its tool acts on: a path for files, a command for commands, a recipient for messages, a tool of a server. These are the teardown's Custom Rules, made exact: a rule names a tool group and a pattern, never free text, because nothing on the gateway can evaluate a sentence (F-174).

**The list**, on the line's page under "Rules about what it acts on": one row per rule, in precedence order (Never, then Ask first, then Allow): "Never · under `secrets/**`", "Ask first · matching `rm *`", with "Edit" and "Remove" (admin). A rule for every bot is listed here too, with the lock-free mark "A rule for every bot" and no Edit; it is edited in Settings, Permissions.

**Adding one.** "Add a rule" opens a form in place (F-174):

- "When Otto wants to:" the line's action, fixed ("Change files");
- "acting on:" a field with the line's kind of pattern, its placeholder an example ("For example, secrets/**"), and under it what it matches: "A path in Otto's workspace. * matches within a folder, ** across folders." / "A command. * matches the rest of a word or line." / "A bot's name." / "A tool of coder, or *";
- "It should:" a select, "Allow without asking", "Ask first", "Never";
- "Add rule" (primary), disabled until the pattern is filled, and "Cancel".

**Limits** (Clawtrate's choices, checked by the plugin and before it by the form; F-332, F-416): each scope (every bot, and each bot) holds up to 20 allow rules and 20 ask rules; Never rules are not limited, since a deny only narrows. A rule's pattern is up to 1,000 characters.

| Case                                                       | What happens                                                                                                                                                              |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A pattern of 1,000 characters                              | Saves                                                                                                                                                                     |
| A pattern of 1,001 characters                              | Under the field, in `--danger`: "A rule can be at most 1,000 characters. This one is 1,001." The field is invalid; nothing is saved                                       |
| A 21st allow rule in one scope                             | "Otto has 20 allow rules, the most a scope can hold. Remove one to add another." Nothing is saved                                                                         |
| A 21st ask rule in one scope                               | The same, for ask rules. An allow rule still saves in that scope, and another bot's scope still takes an ask rule                                                         |
| "Always allow" on a card when the scope has 20 allow rules | The oldest allow rule in that scope is removed and the resolved card says "Replaced the oldest rule: 'Allow under drafts/**'." The removed rule no longer applies (F-416) |
| The same pattern and action already exists                 | "Otto already has this rule." Nothing is saved                                                                                                                            |

Without the rules plugin there are no rules about what a tool acts on: the heading reads "Rules about what it acts on need Clawtrate's rules plugin." and nothing else.

## 9. Activity

Activity answers "what did my bots do with their tools, and what allowed it". It lists every tool action the gateway's audit log holds, newest first, with what decided it where that is reported (F-324).

**A row**: the time; the bot; the task's name; one line in the step card's words ("Changed notes/disk-2026-11-16.md", "Ran du -sh /srv", "Tried to change secrets/api.env"); a tag, **Allowed**, **Asked** (then answered: "Asked · allowed once"), **Denied** or **Blocked**; and the source on the second line: "A saved approval: change files under notes/**, for 1 hour", "Your answer: allow once", "Otto's rule: never under secrets/", "The gateway's command allowlist", "Automatic review: low risk", "Otto's messaging settings", or **"Not reported"**. Opening a row shows its facts (run, tool, times, the gateway's record id) and "Show in chat", which opens the step in its task when the conversation holds it (`work-pane.md` §10).

**Filters** above the list: a select for the bot, and a `.seg` for the verdict: All, Allowed, Asked, Denied, Blocked. "Allowed" has a sub-filter, "By a saved approval", which answers "what did this bot do that I allowed, and under which grant": each row then names the grant.

**Where the facts come from**, and the line at the list's foot that says so:

- The gateway's audit log (`audit.activity.list {kind: "tool_action"}`, `operator.read`) gives each call's start and end, its tool, bot, task and run, and a hash of its call id; never its arguments or result (section 20, row 13). The step card is found by the run and the hash of its own call id.
- What asked and who answered comes from the gateway's approval history (the approvals scope); what the automatic review decided comes from the review's events Clawtrate saw; what rule or grant passed or refused a call comes from the rules plugin's record of its decisions (section 21). Anything none of these covers is "Not reported", never guessed.
- "The gateway keeps 30 days of activity, up to 100,000 records, without arguments or results. A call to a tool the gateway removed leaves no record here; it shows only in its task." (A denied tool's call left no record, section 20, row 13.)

**States**: loading (grey rows); couldn't load; empty ("No tool activity in the last 30 days."); the gateway records none ("The gateway isn't recording activity: its audit log is switched off in its settings." with no action); read-only (sources from approvals show "Needs approvals access"); more than a page ("Show older").

## 16. Usage and context

Usage is the gateway's own numbers, with their source and their age, and nothing else (F-232). Every figure names the period and says "From the gateway's usage records, as of 5:41 PM." A figure the gateway does not report reads "Unavailable", never 0; a figure still being counted reads "Still being counted".

**A bot's Usage row** in its settings: "This week: 1.59M tokens · about $3.18". It opens the bot's Usage page:

- **Period**: a `.seg`, Today, This week, 30 days. A week starts Monday 00:00 in this person's time zone.
- **Tokens**, a fact block: Input, Output, Cache read, Cache write, Total, from `usage.cost {agentId}` and `sessions.usage`.
- **Cost**: "About $3.18, estimated by the gateway from its configured prices, in US dollars." When the gateway lacks a price for a model: "Cost unavailable for scripted/dev-1: the gateway has no price for it." When the provider reports a balance of its own (`usage.status`), it is shown separately, as the provider's: "xAI reports a balance of $12.40." A cost is never computed by Clawtrate.
- **By task**: the bot's tasks with their totals, largest first, each opening the task.
- **By source** (F-131, F-237): "Your messages", "Routines", "Messages from other bots", "Not attributed", as bars with figures. Routines come from their runs' session keys and the routine history; messages from other bots from runs whose id a send returned and turns the gateway marks as coming from another bot. What cannot be tied to one of these is "Not attributed", and a recipient task's whole total is never charged to one message.
- **Context**: for the open task, "Context: 41,200 of 128,000 tokens", from the task's context figures, and "Compact" where the gateway suggests it (`conversation.md`'s task header owns the action). "What fills it isn't reported: the gateway counts input, output and cache, not history, memory or tools apart." (F-233)

**Settings, Usage**:

- **Provider limits** (F-235): each provider window the gateway reports, "OpenAI · Weekly · 62% used · resets Nov 20" with a meter; "No limits reported" for a provider that reports none. From `usage.status`.
- **By bot** (F-237): bars for each bot, with "By source" as a `.seg` beside "By bot".
- **Budgets** (section 17): every budget, its use and its mark.

**Near a provider's limit** (F-236): at 90 percent of a reported window (Clawtrate's choice), or when the gateway reports a run waiting on a rate limit, a banner above the composer of each bot on that account, with a close button: "OpenAI reports 92% of the weekly limit used on OpenAI · Work. It resets in 2 days." At the limit: "OpenAI's weekly limit is reached on OpenAI · Work. Otto's runs wait or fail until Nov 20." Closing hides it until the figure changes.

## 17. Budgets

**Setting one**: in the bot's Usage page, "Set a budget": "Daily" or "Weekly", a number field ("Tokens", at least 1,000, whole numbers), counting the gateway's total tokens for the bot ("Counts the total the gateway reports: input, output and cache.") and, for a routine, its runs. "Save budget". A budget for a routine is set from Settings, Usage, Budgets, "Add a budget", choosing the routine.

## 18. In the conversation

What the controls change in a task, in the components of `conversation.md`:

- **A refused call**: the action card's Not run outcome, with section 3's "Decided by" line. "Edit rule" in its opened view opens the line's page in the bot's Settings tab (admin to change; anyone can read). (F-334, F-337)
- **An ask from a rule**: the approval card (`conversation.md` §12) with "Asked because of Otto's rule '…'." and "Edit rule" in the full request, its 10-minute footer, and Allow once, Always allow… and Deny. (F-335, F-336: with a gateway denial the call is blocked first and no card appears.)

Then "Allow and save", Back, Deny. When the scope is full, the resolved card adds "Replaced the oldest rule: '…'". (F-167, F-416)
- **After a plugin ask expired**: "Always allow next time" in the opened card saves the grant for future calls only: "Rule saved for next time. Nothing was run." (F-328)
- **Saved to memory** (F-110): a grey event line where the bot's file tool wrote `MEMORY.md`, `USER.md` or a note, or where the memory plugin reports a write: "Saved to memory: memory/2026-11-18.md" or "Updated what Otto always remembers". It is a link: it opens the bot's memory page at that item. A write made by a command gives no line; nothing reports it.
- **Budget lines and the limit banner**: section 17 and 16.
- **The Messaged card's policy states**: section 11.

## 21. The plugins

Three plugins make the parts the gateway cannot do. Each is written from this list, each item meant to be checked by a test or a review, and each gets its own security review before it is installed on any gateway that is not a development gateway. Clawtrate detects each from `hello-ok.features.methods` (row 31). The plan's two proposals, the rules plugin (P5) and the memory plugin (P2), are confirmed with the corrections below; the budget plugin is new.

### Clawtrate's rules plugin (`clawtrate-tool-rules`, P5)

**What it must do.**

- [ ] Register one `before_tool_call` hook for every tool (no matcher), at a priority above ordinary hooks. It needs no conversation access.
- [ ] Decide in this order, and return the first: a deny rule that matches, from the bot's scope or every bot's (`block: true`, `blockReason` naming the rule in plain words: "Otto's rule: never change files under secrets/"); an ask rule that matches (`requireApproval`); a grant in scope that has not run out (no decision, the call goes on to the gateway's own checks); "Ask when nothing else decides" when it is on (`requireApproval`); otherwise no decision.
- [ ] Match a rule on the tool's canonical name (its line's tools) and, for rules about what a tool acts on, on one parameter per kind: a file tool's path (`params.path` and the host's `derivedPaths` for patches), a command's text (`params.command`), a send's recipient (`params.agentId`, or the bot id in `params.sessionKey`), a server's tool name. A call whose parameter cannot be read is matched as if it acted on everything: a deny for any path applies, an allow for some path does not.
- [ ] Apply incoming messaging rules on the sender's `sessions_send`: resolve the recipient bot and apply that bot's "Other bots may message" rules, refusing or asking before the message leaves.
- [ ] Ask with `title` "Otto wants to <verb>" (at most 80 characters), `description` saying what the call acts on and the rule that asked (at most 512, no secrets), `severity: "warning"`, `timeoutMs: 600000`, and `allowedDecisions` with `allow-always` only when a grant can be saved for that call.
- [ ] Save a grant only from `onResolution` receiving `allow-always` for its own request, with the scope and lifetime Clawtrate's form prepared for that request (`grants.prepare`, keyed by the request's task and call id); with nothing prepared (an answer from another surface), save the narrowest: this bot, one hour.
- [ ] Enforce the limits of section 6 in the plugin, not only in the form: 20 allow and 20 ask rules per scope, patterns of at most 1,000 characters; on `allow-always` in a full scope remove the oldest allow rule and return it, so the card can name it.
- [ ] Keep a decision record, metadata only, for 30 days: time, bot, task key, run id, the call id hashed as the audit log hashes it (`sha256:` and 64 hex digits), tool, decision (passed, asked, blocked) and its source (a rule's id, a grant's id, "nothing else decides", or none). Never arguments, results or patterns' matches.
- [ ] Methods: `clawtrate-tool-rules.get {agentId?}` (`operator.read`): rules for that bot and for every bot, the fallback switch, `version`; `clawtrate-tool-rules.set {agentId | "*", rules, fallback, expectedVersion}` (`operator.admin`): `{version}` or `{conflict: true, current}`, refusing a rule past the limits; `clawtrate-tool-rules.grants.list {agentId?}` and `grants.revoke {grantId}` (`operator.approvals`): revoked, already revoked or not found; `grants.prepare {sessionKey, toolCallId, scope, lasts}` (`operator.approvals`); `clawtrate-tool-rules.decisions.list {agentId?, runId?, cursor?}` (`operator.read`).
- [ ] Event `plugin.clawtrate-tool-rules.changed {agentId, version}` at `operator.read` after every change to rules or grants.
- [ ] Fail closed: when its rules cannot be read, block every call it would have decided, with "Clawtrate's rules couldn't be read, so this was blocked."

**What it must never do.**

- Rewrite a call's parameters, or return `params`.
- Pass a call the gateway refuses, or register a trusted tool policy to get ahead of the gateway's own: it only narrows.
- Ask or block for `ask_user`.
- Let a grant or an allow rule outrank a deny or an ask, from any scope.
- Mint a grant from anything but `allow-always` on its own request, or from the conversation's words.
- Store a call's arguments or results, or log them.

### Clawtrate's memory plugin (`clawtrate-memory`, P2)

Confirmed from the plan, with three corrections: it is needed only for notes and shared folders, because the gateway's own file writer already takes `MEMORY.md` and `USER.md` (row 16); it records who saved what, which nothing else does; and it never claims a reindex it cannot do.

**What it must do.**

- [ ] Methods `clawtrate-memory.list {agentId | shared}`, `read`, `write {path, content, expectedHash}`, `delete {path, expectedHash}`, `move {from, to, item}` (for pinning a note's item into `MEMORY.md` and back), registered at `operator.admin` except `list` and `read` (`operator.read`). Paths are confined to `memory/**/*.md` in the bot's workspace, and to the folders in `memory.search.extraPaths` for shared memory; resolved and checked as real paths inside those roots, with no links followed out.
- [ ] Locate a bot's workspace with `api.runtime.agent.resolveAgentWorkspaceDir` (unverified from a plugin not bundled with the gateway; prove it first on a development gateway) and refuse to act when it cannot.
- [ ] Refuse a write whose `expectedHash` does not match, returning the current hash and content.
- [ ] Record, metadata only, who saved each memory file: an `after_tool_call` observer for the file tools on memory paths records the bot, task and time (no content); its own writes record the device. Expose it with `list`. A write by a command is not recorded and is not claimed.
- [ ] Emit `plugin.clawtrate-memory.changed {agentId | shared, path, hash}` at `operator.read` after each write, and on each observed file-tool write to memory.
- [ ] Report whether a changed note is searchable only from what the memory backend reports (`memory.status`, a search), never from its own write.

**What it must never do.** Write outside those roots, or any file the gateway's own writer owns (`MEMORY.md`, `USER.md` go through `agents.files.set`); delete a folder; store or log memory content anywhere but the files themselves; call a reindex command unless the gateway's owner supported one for this gateway.

### Clawtrate's budget plugin (`clawtrate-budgets`, new)

**What it must do.**

- [ ] Count every model call's usage per bot and per routine from `llm_output` (`totalTokens` as the gateway totals it), in the plugin's own state, by day and by week in each budget's time zone.
- [ ] Refuse a run at its start with `before_agent_run` (`{outcome: "block", message}`) when the bot's or the routine's budget for the period is used up, with the message "Otto's weekly budget is used up. It resets Monday at 00:00."; never stop a run already going.
- [ ] Emit `plugin.clawtrate-budgets.state {agentId | jobId, used, limit, period, resetsAt}` at `operator.read` at 80 and 100 percent and on every change of a budget.
- [ ] Methods `clawtrate-budgets.get` (`operator.read`) and `clawtrate-budgets.set {target, period, tokens, timeZone, expectedVersion}` (`operator.admin`).
- [ ] Say in its setup what it needs: the gateway's owner sets `plugins.entries.clawtrate-budgets.hooks.allowConversationAccess: true`, which lets it read conversations; without it the plugin registers no gate and reports itself as not enforcing.

**What it must never do.** Keep, log or send any prompt, reply or tool content it can read (only token counts); refuse anything but the start of a run; replay a refused run; treat an estimated cost as a budget.

- Editing the gateway's settings for every bot from Clawtrate: shown, locked, on purpose (section 2).

- The phone's own permission requests and the Secure Form (`conversation.md` §24).
- The computer plugin's install and its bot list: `work-pane.md` §19 and the plugin's own page.
- Context compaction itself (`conversation.md`'s task actions); section 16 only reports the figures.
- A per-turn record of model and effort (F-044), which is `bots.md`'s and the conversation's.
- Which tool a bot uses to create another bot is not in the capability map: section 10 covers the `gateway` and `plugins` tools; a bot that runs the gateway's command line through `exec` is covered by Run commands.
