# A bot's life: the primary bot, editing, copies and deleting

What happens to a bot after it is created: which bot is the primary one, how its picture, name, label and instructions change, what a change to its instructions made in a conversation looks like, and how it is duplicated, exported, imported and deleted. This part of the design comes after `visual-language.md`, `conversation.md`, `bots.md`, `work-pane.md`, `controls.md` and `setup.md`, in the same language and with the same tokens.

What must be true is in `docs/parity.md`, rows F-005, F-007, F-026, F-034 to F-041, F-048 to F-050, F-052, F-259, F-265, F-269 to F-271, F-276 and F-464. What the gateway does is in `docs/research/bots-lifecycle.md`, run on a development instance and read in the installed OpenClaw 2026.10.6. Section 12 ties every control to the fact behind it. Section 13 lists the rows reworded, as decided in review.

Two rules sit above the rest. **Nothing is announced that was not read back**: a save, a copy and a delete each say what the gateway has afterwards, step by step, and after a failure in the middle they say what is there and what is not. **What the gateway cannot do is drawn as what is true**: where it has no way to export a bot itself, or Clawtrate cannot make a picture from here, the screen says so plainly and offers what does work.

The prototype is `prototype/lifecycle.html`: `bots.html` with these screens added, its states picked from the address (section 14). The styles are in `prototype/css/lifecycle.css` and the behaviour in `prototype/js/lifecycle.js`. `prototype/tools/checks/lifecycle.mjs` checks them.

## 3. The primary bot

**What it is.** The primary bot has a star and comes first in its group of the rail, and it is the bot Clawtrate offers when something is shared into the app. That is all it does: no gateway method or setting makes a bot "primary" in this sense, and the one setting that names a default bot, `agents.defaults.systemAgent`, also decides where channel messages that no route claims are delivered (research §1). Clawtrate never writes it.

**Where it is kept.** In the preferences of the gateway profile the connection resolves to, key `clawtrate.primary`, value `{bot: <id>, createdAt: <the bot's createdAt, or null>}` or `{bot: null}` for "keep the gateway's default". Devices using that profile read it and follow `users.prefs.changed`. A profile is not a person: an operator connection that signs in with the gateway's token or password and has no authenticated user of its own resolves to the gateway's owner profile, as does every operator connection without one when the gateway has no roles configured, so every such device shares one choice (research §1). When the gateway answers `no_durable_identity`, the value is kept on the device, as F-266 keeps a manual order.

**Its place in the rail.** First in its group: first among the pins when it is pinned, otherwise first among the bots below the pins. This holds in every sort, Manual included; the other bots keep the sort's order, and a manual order saved for the primary bot is used again once it is no longer primary.

**Before a choice.** The star is on the gateway's default bot, `agents.list` `defaultId`, which the built rail already marks; the Manage group says "Yes, as the gateway's default".

**Introducing the primary bot** (F-007). Shown once, after setup, when the gateway lists more than one bot and the key is absent. Title "Introducing the primary bot"; the default bot's picture at 104 px with the star; "Your primary bot has a star and comes first in its part of your list: first among your pins if you pinned it, otherwise first after them. It's the bot Clawtrate offers when you share something into the app." and "<Default> has the star until you choose: it's the gateway's default bot." Then where it is kept (below). Buttons: "Use an existing bot" (primary, focused), "Create primary bot" (admin only; it opens New bot, `bots.md` §3, and the bot it makes is saved as primary once the gateway lists it), "Not now" (saves `{bot: null}`, so the dialog does not return, and announces "<Default> keeps the star, as the gateway's default bot").

**Choose a primary bot** (F-259), from "Use an existing bot", from the primary bot's menu item "Replace with different bot", and from Manage. A search field (focused), the bots as a radio group with picture, name, label and, under each, "Your primary bot" and "The gateway's default bot" where they apply; the current one checked. Under the list, where it is kept:

| The gateway keeps preferences for this connection | The line                                                                                                                                                           |

| Yes                                               | "This saves a Clawtrate preference for the current gateway profile. Devices using that profile see the same choice. The gateway's routing default stays the same." |
| No (`no_durable_identity`)                        | "This device only: this connection has no profile on the gateway to keep it in, so your other devices won't show it."                                              |

and "The gateway's own default bot stays <Default>. Clawtrate doesn't change it: the gateway uses it for messages no route claims." "Confirm" is disabled until another bot is checked.

| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

"Make primary bot", on any other bot's menu and in its Manage group, saves at once with the same states. The primary bot's menu has "Replace with different bot" where others have "Delete…", and its Manage group's Delete is disabled with "<Bot> is your primary bot. Choose another primary bot before deleting it." A stored choice applies only to a listed bot with its id and the same `createdAt`. When the stored bot is no longer listed (deleted elsewhere), the star falls back to the default bot, Manage says "Yes, as the gateway's default", and the key is left as it is until the person chooses again. When the id is listed with a different `createdAt`, it is a bot made since under a deleted bot's id: the choice is not applied, the star falls back the same way, and Manage and Choose a primary bot say "Your saved choice named a bot that was deleted; a bot made since has the same id, so it isn't used. Choose a primary bot." A bot the gateway keeps no creation record for (one written into its configuration by hand) has no `createdAt` either time, so a hand-made replacement under the same id is not told apart.

## 4. The picture

The hero's picture, on an admin connection, is a button, "Change <Bot>'s picture", with a small picture badge on hover and focus. It opens **<Bot>'s picture**, three tabs: Bot, Generate, Upload (F-037, F-269, F-270). Below admin the picture is only a picture.

**Bot.** The live picture at 104 px, then: "The gateway keeps <Bot>'s picture, not the shape and colour it was drawn from. Pick both to draw a new one." Then `bots.md` §3's eight bodies and eight colours, none chosen at first, because the gateway does not keep which were. "Set picture" is enabled once both are chosen; Clawtrate draws the character and sends it as a PNG `data:` URL of at most 32,768 characters, as New bot does.

**A picture at an outside address.** The gateway can return a bot's picture as an `https` address (`agents.list` `identity.avatarUrl`), which the built client today hands straight to an image element. This design follows `decisions.md`, "Addresses a gateway hands the client": wherever a bot's picture appears here (the rail, the hero, the chooser of section 3, the export screen and the import review), the bot's character is drawn until the person allows that bot's picture at that exact address, on this device. The hero shows the choice: "<Bot>'s picture is at <the full address>. Loading it lets whoever runs that address see this device's network address and the time of each request." with "Load picture". The allowance is kept in the app on the device, per gateway, bot and exact address, and written nowhere on the gateway; a different address is drawn as the character until it is allowed, and an allowed picture follows no redirect. The choice is offered only where that rule lets a platform hold it: on the desktop, once its credential and redirect checks pass. Until then, and always in the web preview and on the iPhone, the character stays and the hero says "<Bot>'s picture is at <the full address>. This app doesn't load pictures from other addresses." An `http` address, another scheme, or a `data:` picture that isn't a PNG, JPEG, WebP or GIF is never loaded: "<Bot>'s picture is at <the full address>, an http address, which Clawtrate doesn't load." A Clawtrate file never carries an outside picture: export leaves it out, and a file's picture must be a `data:` image that decodes (section 9).

**Generate.** Whether the gateway offers the bot its image tool is read from `tools.effective` for the bot's latest task. A tool listed as available doesn't say a provider is ready, and what a client gets back is not settled: research on it is on `origin/r5-image-tool-research` (`docs/research/image-generation.md`, pull request #172, not merged; its review asks for fixes). By that note, a picture comes back in the bot's task, not to this screen: at once or in a later run of the gateway's own, depending on whether the task is bound to a saved session (the gateway also serves it by its path over an authenticated route, tried only with a development gateway's own credentials); a refusal, a provider error and a provider that never answers look the same to a client; and only the picture's bytes, as a `data:` picture read back from the bot list, could be saved, never the gateway's ticketed address. So the tab draws nothing as working:

| What `tools.effective` says      | The tab shows                                                                                                                                                                                                                                                                |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `image_generate` `excluded`      | "Image generation isn't available on this gateway" and "The gateway doesn't offer <Bot> its image tool: “<the gateway's reason>”, in the gateway's own words."                                                                                                               |
| `image_generate` `unavailable`   | "Image generation isn't available on this gateway" and "The gateway lists its image tool for <Bot> as unavailable: it has nothing to make pictures with."                                                                                                                    |
| `image_generate` not listed      | "Image generation isn't available on this gateway" and "The gateway doesn't list an image tool for <Bot>'s task."                                                                                                                                                            |
| The bot has no task to ask about | "Not known yet" and "The gateway says which tools <Bot> is offered for one of its tasks, and <Bot> has none yet. Start a task, then look here again."                                                                                                                        |
| The read failed                  | "Couldn't read the tools" and "Clawtrate couldn't read which tools the gateway offers <Bot>: the gateway didn't answer." with "Try again"                                                                                                                                    |
| `image_generate` offered         | "Generating a picture isn't available in this version" and "The gateway lists an image tool for <Bot>, which doesn't say a provider is ready, and a picture would come back in <Bot>'s task, not to this screen. You can ask <Bot> for a picture in a task, then upload it." |

"Generate" is disabled in every state.

**Upload.** A drop area: "Drop an image here", "Browse files", "PNG, JPEG, WebP or GIF, under 25 MB." Then:

| State        | It shows                                                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Chosen       | The crop, Zoom, and "<file> · <size>. Drag to move it in the circle. Clawtrate saves the circle's square at 128 by 128 pixels." "Set picture" |
| Too large    | On `--warn-soft`: "**That image is 31.4 MB.** Choose one under 25 MB. <Bot>'s picture is unchanged."                                          |
| Not an image | On `--warn-soft`: "**<file> isn't an image.** Choose a PNG, JPEG, WebP or GIF file."                                                          |

The 25 MB check is the file's, before cropping. What is sent is the crop, 128 × 128, encoded and then measured: it is sent only when its `data:` URL is at most 32,768 characters (Clawtrate's bound, which is also well within the gateway's 2 MiB; research §3), and is encoded again at a lower JPEG quality until it is. On the phone, Upload offers "Choose from Photos" and "Take Photo" in place of the drop area and "Browse files" (F-270), then the same crop.

**Saving**, from either tab: "Saving…" on the button; then `agents.list`.

| The read back                         | It shows                                                                                                                                                        |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `avatarUrl` is the picture sent       | The dialog closes; the hero, the rail and the title pill show it; "Picture saved"                                                                               |
| The write was refused                 | On `--danger-soft`: "**The gateway didn't save the picture:** it refused the change. <Bot>'s picture is unchanged."                                             |

## 5. The name and the label

**The name** (F-038, F-026). In the hero, on an admin connection, the name is a button, "<Bot>. Rename". Clicking it turns it into a field in place with the text selected. Enter, or leaving the field, saves with `agents.update {name}`; Escape puts it back. While saving, the field is read-only and "Saving…" is under it. Then the name is what `agents.list` returns, which can differ from what was typed, and "Renamed to <name>" is announced. An empty name is not sent: "A bot needs a name." A refusal keeps the field with the typed text: "Couldn't rename: the gateway refused it. The name is still <Bot>." In the rail, a double-click on a bot's name, or "Rename" in its menu, makes the same field in the row, with the same rules. Any admin connection can rename: the gateway has no owner check. Renaming keeps the id.

**The label** (F-039, F-271). Under the name: the label, or "Add a label" in `--text-faint`, as a button. It edits in place the same way and saves `agents.entries.<id>.identity.theme` with `config.patch`; an empty label removes it ("Label removed"). A rename keeps the label (research §2). On the phone the label is called "Title": the empty one reads "Add a title", and its field is named "Title" (F-271).

Below admin, the name and the label are text.

## 6. Instructions

The About group keeps `bots.md` §8's Description row as that document places it. Its Instructions row reads "AGENTS.md, 5 lines · SOUL.md, 1 line" and opens the **Instructions** page inside the Settings tab (F-040), with a quiet round Back.

The page: "<Bot>'s instructions and personality, as the gateway has them. The gateway controls when it loads these files and how much of them it includes. Changed <date and time>." A bot's own and the gateway's settings set how much of a file is loaded, and a run can read the files again or not at all (research §5), so the page gives no figure and no promise about which copy a task uses. Then two fields in mono, each with its file:

- **Instructions** · AGENTS.md: "How it works: rules, priorities, what to do and not do."
- **Personality** · SOUL.md: "Its tone and manner."

Then: "Memory is separate: what <Bot> remembers is under Memory, and these files don't change it." Memory (MEMORY.md, USER.md and notes) is `controls.md` §12's page; nothing here reads or writes it.

"Save" is enabled once either file differs from what was read. It writes each changed file on its own, with the hash that file was read with, then reads that file again. The gateway takes one file per call and answers for that file alone (research §5), so each file gets its own row under its field, from its own read-back:

| The file's read-back                 | Its row, and what follows                                                                                                                                                                                                                            |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The hash of the text sent            | "AGENTS.md: Written, read back at 5:44 PM". "Instructions saved" when every changed file reads so                                                                                                                                                    |
| Refused as changed since it was read | "SOUL.md: Changed on the gateway", and on `--warn-soft`: "**SOUL.md changed on the gateway while you were editing.** Your text is kept here. The gateway now has:" with its text, "Save mine over it" and "Use the gateway's"                        |
| No answer, or a read that failed     | "AGENTS.md: Couldn't check", announced "AGENTS.md: couldn't check", and "Clawtrate couldn't read AGENTS.md back: the gateway didn't answer. Your text is kept here. Check again only reads it." with "Check again", which rereads and writes nothing |
| Below admin                          | The two files as text, and the admin bar: "Changing <Bot>'s instructions needs admin access."                                                                                                                                                        |

The only instruction override is "Save mine over it", with the hash of the displayed gateway text. On a changed hash it writes nothing, shows the newer text ("**SOUL.md changed on the gateway again.**") and asks again. The other file's row is unchanged. Drafts, file hashes and outcomes are kept by bot id, and Save copies the selected bot's draft at submit: switching bots never shows or saves another bot's draft. The gateway sends nothing when these files change (research §5), so the page finds out about another change when it saves, from the gateway's refusal, and not before.

## 7. A write to the instructions, in the conversation

**What it is on this gateway** (F-041). The gateway can load AGENTS.md and SOUL.md into a run. The gateway keeps no earlier version of either file and nothing attributes a change to a call: a read reports the file's modification time, not who made the change, and another connection can change the file in the same window. So in this unit the conversation says only that a file tool named the file and when the gateway reports it was modified. It shows no difference and offers no Undo. F-041 keeps its target, a difference with Accept and Undo, and stays `todo` until the gateway, or a plugin of Clawtrate's, keeps the version before a write and names the call that made it.

**When the line is drawn.** All of these, and nothing less:

- A `write`, `edit` or `apply_patch` call in the run ended without an error.
- One of the paths it names, read as the Work pane reads a step's paths (`filePathsOf`, `packages/core/src/file-paths.ts`: the path argument of `write` and `edit`, and every file a patch adds, updates or moves), is `AGENTS.md` or `SOUL.md`.
- The task works in the bot's own workspace, established as the Work pane establishes it (`docs/design/work-pane.md`, Part 1, "Which file a path names"), so that the path names the bot's file and not a file of the same name in another folder.
- A read of that file in the matching workspace with `agents.files.get` after the call returns a modification time (`updatedAtMs`) within the run. Without that timestamp the line is omitted.

When any of these fails, there is no line. A change made by a shell command, on the gateway's machine, by another app, or by a run while no client was connected leaves no line either.

**The line.** An event line: "AGENTS.md · modification time <time>". Opened: "A file tool named AGENTS.md. The gateway reports a modification at <time>. It doesn't report who made it." with "Open instructions", which opens section 6's page. A modification by another connection in the same window reads the same: the line attributes nothing. It is the same at every tier: it writes nothing.

## 8. Duplicate

"Duplicate…", in a bot's menu and its Manage group (admin), opens **Duplicate <Bot>** (F-048):

- "Name of the copy", filled with "<Bot> copy", focused. The gateway makes the copy's id from its name and refuses a taken one; the refusal is shown under the field in the gateway's words.
- **Copied to it**, a checklist, all ticked:
  - "Picture and label": "The picture the gateway has for it, and its label."
  - "Model, account and effort": "<account>, <model>, effort <level>. Written as New bot writes it: the model with its account, then an empty fallback list." It follows `bots.md` §3's contract: `agents.create` with `<provider>/<model>@<account>`, then `fallbacks: []` with `config.patch`, then `agents.list`. When the bot's account is kept by the bot alone (`bots.md` §7, "Kept by one bot"), the item reads "Model and effort, on an account you choose", "<label> is kept by <Bot> alone, so the copy can't use it.", and a radio list follows: the shared accounts and, last, "Let the gateway choose" ("The copy gets <model> with no account: the gateway picks one of the provider's accounts for each run."). Duplicate waits for a choice. Unticked: "Without it the copy uses the gateway's default model, <default>, and its default effort."
  - "Instructions and personality": "AGENTS.md and SOUL.md, as they are now. A file the source doesn't have leaves the copy's starting file."
  - "Tool permissions and skills": "What it may do with its tools, and which skills it has."

- "The copy is a new bot with its own workspace folder. Nothing links it to <Bot> afterwards: changing one doesn't change the other."

**The writes, each with its own read-back.** "Duplicate" makes the bot (`agents.create` with its name, picture and model), then writes each ticked setting (one `config.patch` for the label, the empty fallback list, the effort, the tool permissions and the skills; one `agents.files.set` per instruction file), then reads each back. A source file that is missing is not written: the new bot keeps its starting file. A destination file known to be absent is written with `expectedMissing`, one that exists with the hash just read. There is no way to make a bot and its settings in one step (research §7), so the dialog shows one row per setting, as it goes and then from what each read returned:

| The new bot's starting value              | "Still has <value>", for example "Still has the gateway's default, Medium" |

| No answer, or the read failed             | "Couldn't check"                                                           |
| The source had no such file               | "No source file. Left the new bot's starting file"                         |

| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Any other row                           | Title "Some settings still need attention"; "<Copy> is listed. 2 settings don't read back as chosen."; the rows; "Check again", "Try again" and "Leave it as it is", as below                                                               |

Use "Check again" for "Couldn't check". It rereads only. "Changed on the gateway" keeps the other writer's value and offers "Review change" with the observed and requested values. "Try again" applies only to identified selected rows whose current values match their observed starting values, and is absent if none qualify. File writes use that known hash or `expectedMissing`. For settings, `config.patch` uses the `config.get` `baseHash` from the read that checked those values, and reads again on a stale-base refusal. A settled row never changes. The new bot's values in the prototype change only for writes whose read-back agrees, so the opened bot agrees with the rows.

If Create loses its reply, the presence of that name or id does not identify the request that created it. The dialog shows "Couldn't confirm creation. The gateway lists a bot called <Name>. Open it to review it.", withholds all remaining writes and offers "Open" and "Close". If the bot list does not answer, it shows "Couldn't check whether <Name> was created." and offers "Check again".

## 9. Export and import

A bot moves between gateways as a **Clawtrate file**: Duplicate's reading half written to a file, and its writing half read from one (section 8), with a smaller payload and the same strength: the same reads, the same writes, each read back. The format is Clawtrate's own, and the screen says so. The gateway's own package commands are not offered in the app; research §8 records what they do.

**What the file carries**, and nothing else: the bot's name, its label and its picture; its model by name (`<provider>/<model>`) and its effort; and the text of AGENTS.md and SOUL.md, each only when the person chose it. **What it never carries**, listed on the export screen and in the import review: "Tool permissions and skills", "Memory and About you (MEMORY.md, notes, USER.md)", "Tasks and their transcripts", "Routines", "Approvals and rules", "Channel routes", "Other files in the workspace folder", and no account binding or sign-in store. Tool settings are left out because a bot's tool settings can name paths and settings of the gateway they were made on (`agents.entries.<id>.tools` admits execution settings such as `pathPrepend` and `safeBinTrustedDirs`), and another person's file would carry them into this one.

**The format.** Plain JSON, UTF-8:

```json
{
  "format": "clawtrate.bot",
  "formatVersion": 1,
  "writtenBy": "Clawtrate 0.4.0",
  "bot": {
    "name": "Wren",
    "label": "Garden",
    "picture": "data:image/png;base64,…",
    "model": "openai/gpt-5.5",
    "effort": "medium",
    "instructions": { "AGENTS.md": "# Wren\n…", "SOUL.md": "Patient and practical.\n" }
  }
}
```

| Field                                      | Type                                                                    | Limit                                                        | Where the limit comes from                                                                                               |
| ------------------------------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| The whole file                             | UTF-8 JSON                                                              | 5 MiB (5,242,880 bytes)                                      | The desktop host saves at most `MAX_SAVE_BYTES` (`packages/core/src/files.ts`)                                           |
| `format`, `formatVersion`                  | `"clawtrate.bot"`, `1`                                                  | —                                                            | Any other value is refused                                                                                               |
| `writtenBy`, `name`, `label`, `effort`     | text; `name` required, the others text or `null`                        | 256 characters each                                          | The engine's cap on a name, `MAX_NAME_CHARS`                                                                             |
| `model`                                    | `<provider>/<model>` or `null`; a reference with `@` is refused         | 256 characters                                               | The same cap; an account belongs to the gateway it was signed in on                                                      |
| `picture`                                  | a `data:` URL of a PNG, JPEG, WebP or GIF image that decodes, or `null` | 32,768 characters, after cropping to 128 by 128 and encoding | What Clawtrate keeps of a picture, `MAX_AVATAR_CHARS`; the gateway accepts 2 MiB and shows nothing past it (research §3) |
| `instructions["AGENTS.md"]`, `["SOUL.md"]` | text; each present only when chosen                                     | 2,097,152 bytes each, in UTF-8                               | The gateway's bound on a bootstrap file (research §11)                                                                   |

Reading goes in this order: the size, then the JSON, then the format and its version, then every field's name (a field the format doesn't define, at any level, refuses the file), then each field's type and limit, then the picture, decoded as an image and checked against its bound. The first that fails refuses the file with its reason, and nothing in it is used. Export checks the same before it writes.

**Export** (F-049), in a bot's menu and its Manage group, at every tier, since it only reads (section 2). **Export <Bot>**: "A Clawtrate file: this app's own JSON format, for another Clawtrate to read. The gateway doesn't know it." The dialog opens on "Reading <Bot> from the gateway…" (`agents.list`, `config.get`, `agents.files.get` for AGENTS.md and SOUL.md) and checks the candidate before it shows anything; a read that fails stays before the review: "Couldn't read <field>. Try again." Then **The file will hold exactly this**, the values as they will be written, each allowed to wrap, model and account text included: Name, Label, Picture (a preview of the exact encoded inline image, "PNG, 128 by 128", or "Left out: it's an outside address" for a picture at an outside address, section 4), Model ("openai/gpt-5.5-mini · its account, OpenAI · Home, left out"), Effort. Then **Instructions, if you choose them**: a check for AGENTS.md and one for SOUL.md, unticked, each with its line count; a ticked file is shown in full under its check. Then, on `--warn-soft`: "The file leaves out account bindings and sign-in stores. The fields you export can contain private text, credentials or paths. Review them before saving." Then **Never in a Clawtrate file**, "Export file…" and "Reload from gateway", which reads a fresh candidate and, when the selected bytes changed, returns to the review with "The bot changed on the gateway since this was read. Review the new values before saving."

"Export file…" builds the bytes from the displayed values and the checked instruction texts and hands them to the host ("Waiting for the save dialog…") without fetching the source again; "Try again" after a failed save sends the same bytes. What the screen says next is what the host reported (`SaveResult`, `packages/core/src/bridge.ts`); only `saved` reports a name:

| The host reported                            | Title, and the sentence                                                                            | Then             |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------- | ---------------- |
| `saved`                                      | "Saved <host name>, <size>"                                                                        | Done             |
| No save on this host: the browser's download | "Download requested", "Your browser decides where the file goes and whether it keeps it."          | Done             |
| `cancelled`                                  | "Not saved", "You closed the save dialog. Nothing was written."                                    | Try again, Close |
| `failed`, `unchanged`                        | "Couldn't save", "<the host's message>. The selected file still contains its previous bytes."      | Try again, Close |
| `failed`, `absent`                           | "Couldn't save", "<the host's message>. The selected file isn't there."                            | Try again, Close |
| `failed`, `saved-anyway`                     | "Export saved, <size>", "The save reported an error, but the selected file contains the export."   | Done             |
| `failed`, `unknown`                          | "Couldn't save", "<the host's message>. Clawtrate couldn't tell what the selected file holds now." | Try again, Close |

**Import a bot…** (F-265), in the gateway menu, which every tier has, and in the "+" menu, which the read tier doesn't (`bots.md` §2): reading a file changes nothing on the gateway (section 2), so a read-only connection can review a file in full, and admin is asked for only at Add Bot. **Import a bot**: "Choose a Clawtrate file. You'll see everything it would create before anything is." and a drop area, "Drop a .clawtrate-bot.json file here", "Choose file…", "At most 5 MB. Reading it changes nothing on the gateway." Then "Reading wren.clawtrate-bot.json…", and either a refusal or the review.

| Refused for                       | On `--danger-soft`: "**Clawtrate can't read this file.** <reason> Nothing in it was used." Then "Choose another file…" |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| An unknown format version         | "Its format version is 3, and this version of Clawtrate reads version 1."                                              |
| Too large                         | "It is 6.2 MB, and a Clawtrate bot file holds at most 5 MB."                                                           |
| A field of the wrong type         | "Its label is a number, not text."                                                                                     |
| A field the format doesn't define | "It has a field Clawtrate doesn't read: “tools”."                                                                      |
| A model that names an account     | "Its model names an account, “openai/gpt-5.5@work”. A Clawtrate file names models without accounts."                   |
| A picture that doesn't decode     | "Its picture isn't a PNG, JPEG, WebP or GIF image that decodes."                                                       |

**The review**, titled "Add <Name>?": the file's picture at 104 px (a decoded `data:` picture; a file has no other kind), the name in a field (prefilled, editable), "Label: <label> · <file>. The file says it was written by <writtenBy>.", and a neutral note: "These files will become instructions the new bot may follow when it runs. Read them first: Clawtrate shows them and doesn't run them, and nothing is created until Add Bot." Then four rows, each folded, each opening to exactly what it holds:

- "Instructions · AGENTS.md · 5 lines, in full", and "Personality · SOUL.md · 1 line, in full", when the file has them: the text, as text.
- "Settings · 3 to write": the model, the effort and "Fallback list: none", each with "Will be written". A model this gateway doesn't list in `models.list` is "Not available here, left out", its effort "Left out with the model", no fallback list is written, and the row says: "With its model left out, Wren uses the gateway's default model, <default>, until you choose one, and its effort is left out with it." Nothing is guessed in its place.
- "Not created · a Clawtrate file never carries these": the list above, and "Nor any account binding or sign-in store: the new bot gets its account the way New bot gives one."

"Add Bot" (admin; below admin, the admin bar: "Adding a bot needs admin access. You can read the whole file here first.", whose request is the only way admin is asked for) runs Duplicate's writes on what the review said would be written, with Duplicate's rows: "Made <Name>", "Picture", "Label", "Model", "Fallback list: none", "Effort", "AGENTS.md", "SOUL.md", and the same endings: "New bot with the selected settings" ("What its tools, skills and models do can still differ from the bot the file came from: the gateway decides, with its own defaults."), "Some settings still need attention" with Duplicate's "Check again", "Try again" and "Review change", and a lost create's two states, and a taken name under the name field, which can be changed and Add Bot pressed again.

A round trip was run on the development gateway: a file written from one bot and read into a new one gave equal instructions, label, picture, model and effort by the gateway's reads (research §10).

## 10. Delete

"Delete…" is in every bot's menu except the primary bot's, and in Manage (admin). It is disabled in Manage, with its reason, for the primary bot (section 3) and when the gateway has only one bot: "<Bot> is the gateway's only bot, and the gateway doesn't delete its only bot."

A read followed by a delete cannot fence a replaced bot. Delete stays unavailable on gateways without a confirmed current-bot precondition. The states below are drawn for a gateway that has one.

**Reading first.** The dialog opens on "Reading what <Bot> has on the gateway…" while it reads, for that bot, `agents.list` (every bot's workspace folder), `sessions.list` (all its pages), `cron.list` with disabled routines, and `config.get` (its settings and channel routes). If a read fails: "**Couldn't read what <Bot> has.** The gateway didn't answer. Clawtrate doesn't delete a bot without saying what goes." with "Try again" and "Cancel". A number is shown only for a list read to its end; the workspace's files are not counted, because `agents.workspace.list` reads one folder a page at a time.

**Delete <Bot>?** (F-050, F-276, F-464), role `alertdialog`, named by its title, focus on Cancel:

- **The gateway will try to remove**: "<Bot>'s settings"; for each channel route, "Removes this channel route: <channel>, account <account>"; "4 tasks listed for <Bot>"; "Its 2 routines: Weekly plan, Sunday reminder"; "Approvals saved for its commands". It tries these whatever the box below says.
- A check, unticked: "Also move <Bot>'s folders to the Trash on the gateway's machine", then "They can be restored from that Trash, on the gateway's machine, until it's emptied.", and under it, muted until ticked:
  - "The gateway will try to move this workspace, workspace-pip, including its files and memory. It keeps folders still used by another bot." Only when another bot's workspace in `agents.list` is exactly the same path: "Its workspace folder, workspace-juniper, stays: also used by Juniper." The option stays enabled: the gateway has one switch for all of a bot's folders.
  - "Its own folder. May include local sign-ins and other bot data."
  - "Its tasks' transcripts"
- "The gateway checks, while it deletes, which folders another bot still uses." It compares folders that overlap in either direction and other bots' registered folders and databases (research §9), which a client cannot see in advance.
- **Stays**: unticked, "Its folders: with the box unticked, none is asked for the Trash. The gateway may archive its tasks' transcripts."; always, "What <Bot> said in other bots' tasks".
- "This can't be undone from Clawtrate. Before deleting, Clawtrate reads all of this again." "Cancel" and "Delete <Bot>" (danger).

**At Delete.** Clawtrate reads the same lists again ("Reading what <Bot> has again…"). When anything differs from what the dialog shows, it sends nothing and shows the dialog again with, on `--warn-soft`: "**What <Bot> has changed since this opened:** it now has 5 tasks. Check what goes, then delete again." It also compares the bot's creation record (`agents.list` `createdAt`) with the one the dialog opened on, when both exist. If the id is gone or the creation record differs, it sends nothing and the confirmation closes with "The bot you reviewed has changed. Open Delete from its current bot page to review it again." Otherwise it sends `agents.delete` with `deleteFiles` as the box says; the gateway's own default is to delete the files (research §9).

**After.** "Deleting <Bot>…", then the result. The gateway's answer and each read are kept apart: a line says only what its own read or the answer said, and the answer, or its absence, is kept through "Check again".

Under "Read back from the gateway just now:", always all four rows, each from its own read: "Bot list" (`agents.list`), "Settings and channel routes" (`config.get`), "Routines" (`cron.list`) and "Tasks" (`sessions.list`). A row says "Still listed" or "No matching <items> listed" only for a read that succeeded (read to its end, for a list), and "Couldn't check <items>" for a read that failed, was incomplete or got no answer.

The title is "<Bot> was deleted" only when the bot list's read confirms the bot is absent; otherwise "Delete result for <Bot>". The rail follows the same read.

Then, by what came back:

| The answer    | The line                                                                                                                                                                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A refusal     | On `--danger-soft`: "**The gateway refused the request.**" and its reason in quotes; for the bot that holds the shared or inherited sign-ins, "Other bots use sign-ins kept in <Bot>'s folder. The gateway's owner moves them first, on the gateway's machine." Then the same reads. |
| None          | "Clawtrate didn't get the delete result. You asked to <move the folders to the Trash / leave the folders in place>. Check again reads the gateway."                                                                                                                                  |
| `purgeFailed` | Its own line: "The gateway reported a task-store cleanup failure and skipped moving folders on this attempt." The Tasks row stays its own read.                                                                                                                                      |

With the box clear: "No folders requested for Trash", and "No active tasks are listed. The gateway may archive their transcripts." only when the task list read to its end with no tasks. With the box ticked, each path the confirmation named, then any other the answer reported:

| The answer, for a path            | The path's line                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| In `removed`, `method: "trash"`   | "Gateway reported moving this to Trash"                                                                                         |
| In `removed`, `method: "missing"` | "Gateway reported this path was already gone"                                                                                   |
| In `failed`                       | "Gateway couldn't move this: <reason>"                                                                                          |
| In neither, or no answer          | "The gateway didn't confirm what happened to this path", and, for a confirmed match, "Juniper still lists it as its workspace." |

When the answer reported a path moved to the Trash, the lines are followed by "What was moved to the Trash on the gateway's machine can be restored from there until it's emptied." The Trash is the one of the user the gateway runs as (research §9).

"Check again" and "Close" are offered when no answer came, when the answer named a path it couldn't move or reported `purgeFailed`, and when a read couldn't be checked; otherwise "Close". The live region says the title, "The gateway refused the request" for a refusal, and "Clawtrate didn't get the delete result" when no answer came. The result sheets are dialogs with status text; only the confirmation is an `alertdialog`.

"Check again" reads the lists again and shows them ("Read again just now."); it sends nothing and changes no path line. No state offers to send the delete again: a second `agents.delete` carries only the id, and if the first finished, that id can name a bot made since, which the gateway would then delete. When the deleted bot was the person's primary bot, the star returns to the default bot.

## 15. Not covered here

- Generating a picture from the picture editor: what a client gets back from the gateway's image tool is being settled on `origin/r5-image-tool-research` (#172, not merged).
