# The SSH transport's tests

The SSH transport of "Another computer" (`apps/desktop/src/main/ssh/`, [decisions](../decisions.md#ssh-to-another-computer)) is tested by `pnpm test`, in `apps/desktop/test/ssh/`. To run only its tests:

```bash
pnpm exec vitest run apps/desktop/test/ssh
```

- `config.test.ts`, `output.test.ts`, `look.test.ts`, `forward.test.ts`, `http-probe.test.ts`, `world.test.ts`, `guard-links.test.ts`, `app-files.test.ts` and `client.test.ts` need no server. `config.test.ts` reads generated files back with `ssh -G`, which reads a file and connects nowhere. `guard-links.test.ts` replaces the account database's home with one it makes, so it can put links into a `.ssh` folder of its own. `client.test.ts` uses stand-in `ssh` scripts that only print what a test needs. `look.test.ts` also runs the LOOK script under every shell it finds (`sh`, `bash`, `zsh`, `dash`, `ksh`, `csh`, `tcsh`, `fish`) in a home of its own whose start-up files print, and names each missing shell as skipped. One of its checks waits 30 seconds for the script to stop itself.
- `sshd.test.ts` starts `sshd`s of its own: as the current user, on free loopback ports, with host keys, authorized keys, configurations and a home it creates in a temporary folder, and `SetEnv HOME=<that home>`, so sessions read the test home's start-up files and look in its fixed places. One refuses forwarding, one has two host keys. It proves the home with a plain `ssh` before any LOOK runs, and refuses to go on otherwise. The OpenClaw it finds is a stand-in script in that home, and the gateway's port is a loopback HTTP server that answers every request. It stops each `sshd` and every session process by PID, and checks that every `ssh` it started has ended. It takes about 15 seconds.

Nothing of the machine's own SSH setup is read or used. Every `ssh` runs with `-F` on a generated file that names the test's key explicitly, `IdentitiesOnly`, `IdentityAgent none`, and a minimal environment without `SSH_AUTH_SOCK`; a test reads every file it ran back with `ssh -G` and fails on any other key or an agent, and the module itself refuses, under a test run, any path inside the real `~/.ssh` and the real agent. The tests never connect to this machine's SSH port or to any host but their own `sshd`; the "no such name" case is a recorded output, and so is "no answer".

`sshd.test.ts` is skipped, with the reason in its name, where `/usr/sbin/sshd`, `/usr/bin/ssh` or `/usr/bin/ssh-keygen` is missing, where `sshd -t` refuses a test configuration, and on Windows. In CI it runs in the Linux `check` job when the runner's `sshd` accepts the test configuration; the job's log names it as skipped otherwise. One check, "finds nothing in a home without OpenClaw", is skipped where a program exists at one of the script's fixed places outside a home (`/opt/homebrew/bin/openclaw`, `/usr/local/bin/openclaw`), because the script would run it.
